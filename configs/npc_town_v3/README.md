# NPC 小镇

在 Nexarbor 顶部菜单选择「工作台 → 示例应用 → NPC小镇」。首次建立独立的 `build/npc-town-v3` 运行目录，之后重新打开会继续上次存档。也可用「打开应用配置」选择本目录的 profile.json。原来旧协议的小镇配置和数据不覆盖。

左栏底部选择「世界脉冲」，单步推进一个时刻，或填写次数后运行。每天是早上、中午、下午、傍晚、午夜五个时刻。模型使用项目已配置的 Harness 账户，经官方 DeepSeek API 运行；不会打开 Harness 日常客户端。

本场景的 tick 按居民顺序推进，收信者在自己的回合处理便条。普通模块访问仍异步，同层信号仍并行；顺序来自网络连接。多名互相等待对方整轮结束的模型活动不适合放在同一层。孩子在最后一名居民之后活动，再汇合进入存档节点。

如果运行曾被强制中断，先查看已完成的操作，再点「核对中断」保留现状，从新时刻继续。框架不自动重放已经完成的交易。不会因一个存档或普通业务错误就清空网络。

9 个地点、7 名居民保留旧场景的人格、开场目标和初始财产。根节点只是观察入口；没有自主操纵全网的 Agent。

| 效果 | 实现方式 |
|---|---|
| 角色、资产、行动点 | 通用记录仓；每时刻重置10点 |
| 移动、位置、可用工具 | 目的地的移动模块；锁住本人、原地和目的地，扣3点并更新双向位置边；下一次模型请求重新准备现场和工具 |
| 买卖、挖矿、砍树、修理、休息 | 同一份可配置业务服务，地点前端参数区分动作、数量费用、资格、库存及住所 |
| 同地交流、赠送 | 私人消息箱与本人资源转交；只能顺着相应频道访问，花1点 |
| 荒诞传闻、概率奖励 | 本地概率事件；抵达与业务操作按触发类型共用事件次数 |
| 结婚、家庭计划、出生 | 双人协议；双方本人同一时刻同意，计划后等待10时刻，待产者到医院兑现 |
| 孩子独立活动 | 明确安装的官方固定模板端口，产生新的节点、记忆文件与会话；下一次时刻波才激活 |
| 人格、情境知识、私人记忆 | 角色上下文组件；按自己的记录匹配知识，不共享他人的私人记忆 |
| 存档与恢复 | 每次修改增量记录，每5时刻请求全量存档；原生日志位置和核心状态协调保存 |

业务模块由制作 Agent 产出或参考修订，来源见各组件「制作记录.json」。本小镇的网络和出生模板由维护者用声明配置装配，运行无需生成脚本、LangGraph业务流程或兼容层。`scripts/build_town_config.py` 只用于重建配置，客户端运行不依赖它。

位置关系和家庭关系使用不同频道。位置和道路不传递收集器的 tools 频道，防止同地角色互相转调收集器；自己的收集器仍可通过 movement、service、chat 等业务频道收集实际工具。内部记录、事件、模型运行和出生端口不直接暴露给模型。

地点访客从本节点的 location 出边派生，出生模板添上医院到孩子的位置边后就会被计入；不需要另写名单同步代码。

出生需要创建节点，属于明确的官方能力。本应用只登记两个固定家庭模板，调用者白名单限定为对应住处，不接受模块上传代码或任意网络。

组件 Python 运行在可信本地进程内；ctx 是框架权限接口，不是操作系统安全沙箱。测试副本会禁用真实模型与外部工具。真实模型的自主选择和业务确定性分别验收，不能仅凭聊天文字断言交易或出生已发生。
