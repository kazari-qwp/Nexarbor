# 元数据字段（metadata.fields）

版本：0.1.0
格式：nexarbor-module/v3
入口：`module.py:execute`

把本实例配置中的任意 JSON 键值字段发布到所在节点的模块命名空间，并把同一份字段作为结果返回。组件不保存状态、不访问其他节点、不修改节点数据或网络连接。

## 配置

根配置是严格对象，只允许 `fields` 一个字段：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `fields` | 对象 | `{}` | 字段名称到任意 JSON 值的映射；省略时按空对象处理 |

`fields` 的值可以是字符串、数字、布尔、对象、数组或空值，发布和返回时保留原 JSON 类型。例如：

```json
{
  "fields": {
    "标题": "示例",
    "计数": 3,
    "启用": true,
    "配置": {"层级": 2},
    "列表": [1, 2],
    "备注": null
  }
}
```

`example.json` 使用空字段 `{"fields": {}}`。

## 操作：read

- 名称：`read`
- 频道：`metadata`
- 参数：空对象 `{}`；节点 ID 等数据不会改变发布目标，也不是访问凭证。
- 结果：

```json
{"fields": {"标题": "示例", "计数": 3}}
```

每次执行都会先通过 `ctx.publish_metadata` 在本节点的 `metadata.fields` 扩展命名空间下发布当前字段，再把同一份内容作为结果返回。字段只在执行 `read` 操作或响应 `metadata.refresh` 信号时发布；挂载模块本身不会主动执行 Python。

## 信号：metadata.refresh

`metadata.refresh` 是信号频道，不是 activation 上的字符串。收到信号激活时，`activation.signal` 是核心的 `Signal` 对象，组件检查 `metadata.refresh in activation.signal.channels` 后才发布当前字段；同一信号可以同时携带其他频道。频道集合不包含 `metadata.refresh` 时返回中文错误且不发布。每收到一次投递，就按当前配置发布一次字段并返回结果，便于其他节点通过访问或信号触发刷新。信号投递不修改本实例状态。

## 冻结 JSON 与返回副本

`ctx.config`、`activation.parameters`、信号内容和 `ComponentResult.data` 都使用冻结 JSON：对象是 `FrozenDict`，数组是 tuple。直接调用 `execute` 时返回的 `ComponentResult.data` 是冻结值，不能原地修改；需要可修改副本时使用 `datanet.core.json_values.thaw`。通过真实 `NodeModules` 访问调用拿到的结果已经是核心转换后的 JSON 副本（对象为 dict、数组为 list），修改该副本不会影响本实例配置或本节点已发布的元数据。

## 支持节点

`node`、`agent`、`text_file`、`pulse`。挂在 Agent 节点上时只发布元数据，不修改 Agent 的四路输入。

## 错误处理

- 配置中的 `fields` 不是对象时，返回 `ComponentResult(status="error", error="配置项 fields 必须是对象。")`，不发布任何字段。
- 不支持的信号频道（缺少 `metadata.refresh`）、未知操作或未知激活方式均返回中文错误，不发布字段。
- 元数据发布失败时异常向上抛出，不伪装成成功结果。
- 组件不读写 `ctx.state`，不创建全局状态，不获取节点锁，也不发起跨节点访问。

## 客户端页面

清单声明 `frontend: {"entry": "ui.html", "title": "元数据字段", "height": 460}`。页面是自包含 HTML，只通过客户端注入的 `window.NexarborModule` 读取上下文、提交配置和请求高度，不自行建立桥接、不执行 Python、不访问其他节点或宿主数据。

页面采用深色窄面板（约 260 像素起），全部文案为中文：

- “＋ 添加元数据”新增一行；“删除字段”移除该行。
- 每行包含“字段名称”、“字段类型”和“字段值”。“字段类型”可选字符串、数字、布尔、对象、数组、空值。
- 字符串和数字使用文本输入；布尔使用复选框；对象和数组使用 textarea 输入 JSON；空值显示为 `null`。
- “保存配置”一次性调用 `setConfig` 提交完整 `fields`，不会在每次按键时发送配置，因此输入焦点不会丢失；未编辑的其他配置字段会被保留。
- 保存成功后显示“已写入网络草稿，应用网络后生效”，之后仍需在客户端点击“应用网络”才会影响运行实例。
- 保存前校验：字段名不能为空、名称不能重复、数字必须有效、对象/数组必须是合法 JSON 且类型匹配。错误以中文就地显示，不静默覆盖已有值，错误时保留用户输入。
- 数字按 `number` 保存，布尔按 `boolean` 保存，对象、数组和空值分别保留原类型，不会把数字转换成字符串。
- 页面用 `textContent` 等安全方式显示字段和错误；收到相同配置时不重建正在编辑的行，折叠后重新挂载时从 `context.config` 还原已有字段。
- `readOnly` 为真时禁用添加、编辑、删除和保存控件，并显示只读提示。
- 内容或提示变化后调用 `resize`，高度不超过 900 像素。

页面不包含网络请求、外部脚本、弹窗、下载或宿主 DOM 访问。

## 测试

在组件目录运行：

```text
python -m unittest discover -s tests -v
```

测试使用 `unittest.IsolatedAsyncioTestCase`，通过真实的 `NodeModules` 装配运行 `read` 操作和 `Signal` 传播，并使用真实的 `Activation`、`Signal`、冻结 `config` 与 `ComponentResult`。覆盖：

- 字符串、整数、浮点数、布尔、空值、嵌套对象和数组在发布与返回时保留 JSON 类型。
- `read` 操作与 `metadata.refresh` 信号都会发布字段；测试同时检查操作 `status == "ok"`、信号传播完成状态和信号后的节点扩展字段。
- `fields` 缺省、显式空对象两种空字段情况。
- 重复访问、重复信号投递每次都发布一次且结果一致。
- 两个节点实例的配置、发布内容和状态互不串扰。
- `fields` 不是对象时组件返回中文错误且不发布；真实装配时配置 Schema 也会拒绝非对象 `fields`。
- 未知操作、缺少 `metadata.refresh` 频道的真实 `Signal`、缺失信号对象均返回中文错误且不发布。
- 访问 `read` 操作需要 `metadata` 频道；无此频道的调用方被核心拒绝。
- 直接调用得到的冻结返回值不可原地修改；通过 `NodeModules` 得到的 JSON 副本修改后不影响不可变配置与已发布元数据。
- 组件不写入状态。

Python 测试只验证组件业务行为，不覆盖页面 DOM 交互。页面交互需要在客户端实测，步骤见下节。

## 页面验收步骤

1. 在模块折叠区打开“元数据字段”，空配置时显示“暂无字段，点击“＋ 添加元数据”开始。”。
2. 点击“＋ 添加元数据”，出现一行，包含“字段名称”“字段类型”“字段值”和“删除字段”；输入名称与值后保存，确认客户端配置中出现对应键。
3. 类型保留：分别添加字符串、数字、布尔、对象、数组、空值字段，其中对象填 `{"层级": 2}`、数组填 `[1, 2]`、布尔勾选复选框；保存后折叠再展开，确认类型、值和控制形态都还原，数字仍为数字。
4. 点击“删除字段”，该行消失；保存后配置中对应键被移除。
5. 错误输入：字段名为空、两个字段同名、数字填 `abc`、对象填 `[1]`、数组填 `{}`、JSON 缺少引号或括号时，页面就地显示中文错误，不提交配置，已输入内容保留。
6. 点击“保存配置”，页面显示“已写入网络草稿，应用网络后生效”；在客户端应用网络后，访问 `read` 或发送 `metadata.refresh` 可看到相同字段。
7. 重新收到相同配置或折叠重开时，页面展示已有字段，且不会把正在编辑的内容清空。
8. 在只读预览中，添加、删除、输入、类型选择和保存按钮均被禁用，并显示只读提示。
9. 将面板缩到约 260 像素宽，确认无横向滚动、控件可用；内容变化后页面高度自动调整且不超过 900 像素。
10. 确认只有点击“保存配置”才会写入配置，普通按键不会触发配置提交。
