# 理解 Nexarbor

把网络想成一张会工作的关系图：**节点放东西，模块办事情，连接决定谁能找到谁、能做什么。** Agent 是会思考和调用工具的节点。工具是供它调用的操作入口，常由模块提供。

- **信号与调用都沿网络走。** 信号和调用都有初始强度，从初始数值出发，先由接口检查频道与阈值；通过后乘以边的乘数，进入节点再加节点偏置（散度）。过不了门槛或数值变为负数，就不能继续沿该路径传播。调整接线和参数，就能改变行为与可达范围。遍历方式是广度优先搜索
- **信号是一道独立推进的波。** 发出后脱离发起者，按广度优先逐层传播，同层异步并行；普通信号默认不回源，也不返回业务结果。用它表达时钟、事件和广播，不必把接收者串成固定顺序。
- **调用是一次有结果的请求。** 模块主动发起请求，沿可达网络找到目标并执行，最后将结果返回调用者；被调用模块也可以继续发起调用。用它表达查询、交易和其他需要结果的操作。
- **能力放在局部。** 地点提供自己的服务，角色带自己的行为，通用组件只处理自己的职责。知道节点编号也不代表有权访问它；频道、强度和可达路径共同决定访问。
- **到达后直接使用对象。** 模块按频道取得去重的广度节点对象表，再直接读写或调用对象；不拿编号逐个重新寻路，也不按名称、ID或强度重排。需要拓扑变化后的新范围时再查询；接口按需读 `references/lessons/02-network.md`。
- **频道表达关系与用途。** 优先沿专有频道访问，避免先全频道遍历再筛节点；多条线反复携带的冗余频道表应检查能否合并。这既是制作规范，也是验收标准，细则见 `references/lessons/02-network.md`。
- **先组合，再造轮子。** 同类能力通过组件配置适应不同地点、角色和应用。先用现有组件、参数和接线表达需求；确有能力缺口再写职责明确的组件，区分通用能力与应用专有规则。
- **模块可以有自己的小工作区。** 亚节点挂在父节点上，独立放模块、工具和出边；父子仍可作本地调用。这样主节点不必拉满各种用途的线。
- **锁只保护不能暴露的中间状态。** 想清楚“别人看到哪一步会出错”再锁；普通读取、发消息和模型思考不顺手套大锁。
- **画布、运行状态与模型历史各有位置。** 修改草稿、校验应用、Commit 和分叉上下文解决不同问题；复制角色会得到独立身份与数据。

例如：两个商店复用商品交易组件，两个采集点复用服务组件，用参数区分商品、资源与费用；角色移动后按当前位置获得当地工具。应用规则由组件与网络共同表达。

理解陌生网络接着用 `inspect-network`。组装网络用 `make-network`；补充能力用 `make-components`。解释时区分机制、当前配置、运行状态和推断。
