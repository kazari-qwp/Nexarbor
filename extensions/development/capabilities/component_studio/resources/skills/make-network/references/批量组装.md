# 用短命令组装草稿

优先使用 `edit_network(commands=[...])`。每批 1–100 条，失败整批不保存；默认改 network.json，可用 path 指定另一个自有 JSON 产物，新文件从空网络开始。无需拼节点骨架或重复抄写组件默认配置。返回修改数量和简短回执，再按需查看图及节点。多个独立零件的声明与验证见 lessons/06-presets.md。

| op | 字段与含义 |
|---|---|
| node.create | id、kind（node/agent/text_file/pulse/subnode）、name；亚节点还需 parent |
| node.update | node、patch；按对象合并，数组整体替换，不能改 node_id |
| module.mount | node、module，可选 config/state/access；从发布默认装配开始合并，已挂模块保留未指定字段 |
| module.remove | node、module；去掉此挂载 |
| edge.add | source、target、channels，可选 threshold（1）、multiplier（1）、attributes（{}）；单向边，原样重试不重复添加 |
| edge.remove | source、target；可选 metadata 精确匹配，否则移除这两个节点间所有出边 |
| text.write | path、text；项目内相对路径，正文写入网络 files |

最小示例：
```json
{"commands":[
  {"op":"node.create","id":"资料","kind":"text_file","name":"说明"},
  {"op":"node.update","node":"资料","patch":{"parameters":{"file_path":"docs/说明.md"}}},
  {"op":"text.write","path":"docs/说明.md","text":"项目资料"}
]}
```

`module.mount` 的参数来自精确 `catalog_modules` 查询，不猜接口。requires 仍由框架在 validate 时递归补齐。执行配置、亚节点连接开关、offered_tools 等用 node.update 设置；仍受实际核心 Schema 与管理员范围限制。

工具不替你设计拓扑或扩大授权。先少量组装、观察、验证，再扩展同类节点。validate 只证明格式与装配合法；业务还要在独立测试环境中实际调用和检查数据。需要完整节点替换时仍可用 network_patch，不必读写整份大 JSON。

项目已有预设时，先用 `catalog_presets` 查看摘要，`instantiate_preset(id,count)` 按重复人数放入草稿，再按返回的实际编号映射连接组入口。它复用客户端的复制和核心重复单元机制，自动映射私有文本、prepare 和节点引用，不执行 Agent。
