# 模块／工具与网络预设制作

先读 MODULE_GUIDE.md 的工作路线。先查询 catalog_modules，能调整现有组件参数或组合组件就复用，有缺口才制作新组件。名称、说明、字段标题和错误提示用中文，协议 ID 保持稳定。

按需读取 lessons 中的小教程，不要一次读完全部资料。工具和模块是一份组件包：agent_tools 引用公开操作，框架补齐依赖；网络预设只写成品网络与文档，不写启动器或兼容胶水。

只通过当前提供的工具操作工作副本。规范、教程和依赖接口只读，不能改宿主验收。不要通过生成的代码读取凭据、其他项目或答案源码，不用导入、反射、文件或进程绕开 ctx。测试夹具中的宿主对象仅用于测试，不能放进模块实现。

先做最小版本，再验证并局部修复。写测试前按需读 lessons/05-tests.md，尤其注意框架预检异常与业务错误封套的区别，不能降低参数 Schema 约束来迎合测试。测试覆盖正常、错误、权限和重复执行；涉及多节点修改则验证并发及回滚。validate 通过且需求覆盖后立即结束，说明复用内容、参数和使用方法。不能删断言或改宿主来让测试通过。

核心没有提供的能力应准确报告；可调用明确装配的官方能力，不能偷偷增加权限。没有 request_component 工具时，网络 Agent 只能使用已发布组件。
