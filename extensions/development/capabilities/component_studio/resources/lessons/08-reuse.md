# 需要的是效果，不一定需要新组件

用户描述当前网络的效果后，先查现有组件。有的需求只要填写前端参数，例如把同一业务组件配成采集、买卖、赊账和还款。不要为了交差复制一份实现或发布空白计数器。

模块／工具制作器可以输出 presets.json，代表已发布组件的配置方案：
```json
{"format":"nexarbor-component-presets/v1","presets":[{"module":"已发布ID","name":"方案名称","description":"用途与使用步骤","config":{}}]}
```
必须先查该组件的实际Schema，完整填写合法配置。不要创建新ID；宿主会验证所有引用及配置，发布时保存为独立模块书签，不改已有组件实现或其他节点。

需要理解当前场景时读07，复制网络、试装配置并运行正常/边界流程，在结果中说清哪些行为实际测过。组件配置方案由书签拖入节点使用；跨节点组装由网络制作器或用户审阅后处理。模块制作器不直接修改正式网络。

确实缺少通用能力时，才按01至05制作模块包。网络制作器仍输出network.json；子制作器若返回component-presets，则复用其presets里的module与config组装网络。
