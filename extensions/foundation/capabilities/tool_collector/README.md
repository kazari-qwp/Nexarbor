# 工具收集器

模块 ID：`tools.collector`。组件 ID：`capabilities/tool_collector`。使用 v3 标准入口，不含小镇业务代码。开发工作台默认载入，可以在模块列表装配。

`collect({})` 从所在节点出发，按本实例 access 的强度和频道枚举可达工具；遇到其他节点上的同类模块，就并行调用它的 collect。被调用模块使用自身授权，因此可以继续取得更远处的工具。将结果合并，按原始提供节点＋工具引用去重，优先保留直接访问、其次更短的收集器链。不同节点提供的同名工具保留。

返回数组，每项包含 id、name、description、parameters、origin（node_id/tool）和 via（经过的收集器节点）。不读取全图、其他模块状态或宿主对象。

可收集节点提供的宿主工具，也可收集模块通过 agent_tools 明确携带的静态工具，例如“移动到此”。静态工具引用为 `module:movement.here/move_here`；串联执行仍通过核心按当前路径检查并进入声明操作。核心的 requester_id 在转调中保留最初请求者，不能靠参数冒充另一个 NPC；每一跳的直接调用者仍由 caller_id 表示。

`invoke({"tool_id":"返回的 id","arguments":{...}})` 重新按当前网络收集、检查这个工具，然后直接调用或转调下级收集器；远端工具不被伪装成调用 Agent 的直接可达工具。断开必要路径或移除工具后，旧列表不会继续赋予执行能力。

默认装配：

```json
{"config":{},"state":{},"access":{"strength":2,"channels":["tools"]}}
```

收集器操作通过 tools 频道公开。需要更大范围时更改该实例 access.strength，不更改组件代码。清单的 tool_provider 声明 list/invoke 操作；这是通用 Agent 适配声明，不把所有模块操作自动变成 Agent 工具。Agent 沿授权连接访问挂有该模块的节点，返回工具会装配进其工具列表，之后仍通过模块执行。

按当前约定，不实现收集器环检测、visited 参数或循环截断；若收集器互相递归调用，会重复请求，最终受已有核心通用资源预算限制。普通图遍历的节点去重沿用核心。

验收图：1→2，2→3、4，3→2，4→5→6。1 的收集器强度 2，3 的强度 10；2、3、4、5、6 提供工具。1 直接只能发现 2、3、4，串联后返回 2 至 6 的工具；2 的工具只保留一份；还能沿 1→3 的收集器链实际调用 6 的工具。
