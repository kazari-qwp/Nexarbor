# 移动到此

程序标识：`movement.here`。装在目的地点，携带一个“移动到此”Agent 工具，自动装配依赖“位置资料”。无需 LangGraph。

NPC 与旧地点也应装配“位置资料”，NPC 的初始 location 指向旧地点。NPC 与旧地点之间用 `relation: location` 的双向连接；相邻地点之间用 `relation: road` 的双向道路。位置边频道为 movement、tools，门槛 1、倍率 1。默认模块访问强度 2，频道 movement、tools。

Agent 沿授权网络取得目的地工具，然后无参数调用。实际移动对象来自核心的 requester_id，不接受伪造的 NPC 编号；允许工具收集器转调而保持发起者身份。先锁 NPC、旧地点、新地点，锁内重查位置、双向道路与位置连接，再更新新连接、访客、位置和 Agent 当地说明，最后删除旧位置边。其他调用与信号等待提交，异常或取消回滚内部节点记录。只修改位置边，不删除其他业务连接；超时后可重新请求。

模块本身不增加权限，过远目标、错误频道和非相邻道路均拒绝；没有文件系统或全图入口。移动后的旧工具在执行时仍重查实际路径，新的工具可沿新地点重新取得。

## 移动前钩子

配置项 `before_hooks` 默认是空数组，保持原有移动用法且不引入额外依赖。每项可填写：

```json
{
  "target": "requester",
  "module": "records.store",
  "operation": "apply",
  "arguments": {"deltas": {"ap": -3}}
}
```

- `target` 只能是 `requester`（发起移动的真实 Agent）、`origin`（锁内重查得到的旧地点）或 `destination`（当前目的地点）；目标节点由框架认证的 `ctx.requester_id` 和真实位置映射，不读取参数里的 actor。
- `module`、`operation` 指向已发布的目标模块公开操作，`arguments` 是 JSON 对象。
- 钩子在 NPC、旧地点、目的地都已锁定，且锁内重查位置、道路和位置边全部通过之后执行；此时尚未修改任何位置数据。数组按顺序逐个 `await`，任一步返回非 `ok` 就抛异常，由整个移动事务回滚之前所有钩子的副作用。
- 钩子只调用锁集合内节点的公开操作，不能调用外部工具，也不能自行扩大锁集合。目标模块的频道和路径仍受本实例装配授权约束；需要调用 `records.store` 时，应给移动模块的访问授权和沿途边增加 `records` 频道。

例如 NPC 的行动力预算可完全放在 Agent 自己的 `records.store` 中：

```json
{
  "initial": {"ap": 10},
  "minimum": {"ap": 0}
}
```

移动模块配置上面的钩子即可扣 3 点；不足时记录仓拒绝，位置边、访客和行动点都保持原样。它只是通用顺序钩子，不为 NPC 或某种预算写死规则，也不强制安装记录仓。
