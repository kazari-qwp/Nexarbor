# 公共讨论黑板节点

组件包含实现、工具定义（在Python注册）与创建模板 `node.json`，类型为 `discussion_board`。模板中的节点ID和存储路径由网络装配者替换；每个小组必须使用独立文件路径。

## 能力

- `read({method:"key",key:"content"})`：只读取上一轮固定快照。
- `write(key="content",value=...,mode="append")`：仅向本轮追加区追加；覆盖模式在实现层拒绝。
- `run_discussion(task,rounds=2,strength=0)`：按固定轮数调度成员，使用持续会话，归档每轮记录、更新快照并清空追加区，最后要求Recorder通过获准工具写入成果，返回输出节点ID。

轮次中返回的成员意见由程序统一追加，所有成员收到同一上一轮快照，不提前读取当前轮别人的回答。Leader和Recorder仍按各自角色参与。成员不自行启动讨论调度；最终汇总只是Recorder整理的成果，不代表已达成全体共识。

文件布局：

```text
discussion.md               # 本轮追加区，轮次完成后清空
discussion.previous.md      # 上轮快照
archive/<运行ID>/round_*.md  # 仅供调试，未注册历史读取工具
```

同一节点实例内追加和切换快照使用锁，run_discussion重复触发返回busy；尚不提供跨进程锁或多文件崩溃事务。失败保留未完成轮的追加记录，不自动丢弃；下次启动若发现未归档内容会拒绝，由宿主恢复处理。

## 网络配置要求

参数指定 `members`、`leader_id`、`recorder_id`、`project_id`、`notebook_id`、`output_id`。Leader和Recorder必须在成员列表中且不同。成员需要Agent及黑板到成员的显式委托许可；项目说明和输出文本节点须从黑板读可达。公共笔记和输出的access.write 频道应只给Recorder，私人笔记接口给对应成员。这些接口不由黑板工具自动授予。

成员轮次使用持续Agent会话；每轮作为独立访问请求，从成员自身开始遍历，预算继承其到达强度，不重新注入。Agent调用链保留调用方和黑板，因此循环委托仍被拒绝。这使星形成员能够访问共享黑板，而不是把调度路径误当成数据读取的已访问路径。

运行仍受现有深度和委托次数保护，默认每次最多8次委托。例如三名成员两轮讨论，加Recorder最终整理为7次，符合默认额度。上游已消耗的委托次数也计算在内；超过额度在开始前拒绝。不是并行调度或自动共识判定。

网络JSON已支持该节点类型，网络包会映射内部成员/文档ID并绑定最终网络。当前仅完成节点组件与本地模拟验证，尚未组装完整的小组网络或调用真实模型验证讨论。


## 专用访问

普通read/write入口返回forbidden，也不安装或暴露通用读写工具。成员通过read_round读取上轮快照，通过submit_round/skip_round提交；身份、活动轮次和重复提交由调度器检查。归档与清空仅由内部代码执行。Harness保留成员接口可达性校验。文件权限需另外由Harness沙箱控制。
