# 概率事件（`chance.events`）

一个通用的概率信息组件：配置一组事件，调用方按「触发动作」来抽。每次 `draw` 里，每个适用事件都用自己的固定概率**独立**判定一次；命中才把该事件的累计命中次数加一，达到上限后就不再参与抽取。组件只保存命中次数并返回本次命中的事件，**不修改任何实体资源**，效果的落地由调用方决定。

组件不公开 Agent 工具，也没有信号入口；只有一个供其他可信组件调用的内部操作 `draw`。频道的交集与强度由网络负责，组件不重新实现传播。

## 挂载

- 节点类型：`node`（普通节点）。
- 模块 ID：`chance.events`，版本 `1.0.0`。
- 工具：无（`tools` 为空），不会出现在 Agent 的工具列表里。
- 信号：无（`signals` 为空），不响应任何频道。
- 依赖：无（`requires` 为空）。

## 配置

```json
{
  "events": [
    {
      "id": "rain",
      "triggers": ["explore", "rest"],
      "probability": 0.25,
      "max_hits": null,
      "message": "天空落下细雨，路面渐渐湿了。",
      "effects": {"weather": "rain", "mood": -1}
    },
    {
      "id": "found_coin",
      "triggers": ["explore"],
      "probability": 0.05,
      "max_hits": 1,
      "message": "你在路边捡到一枚旧硬币。",
      "effects": {"item": "old_coin", "amount": 1}
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `events` | 数组 | 是 | 事件定义列表，按数组顺序逐项独立判定。 |
| `events[].id` | 非空字符串 | 是 | 事件标识，同一配置内必须唯一。命中次数以它为键保存。 |
| `events[].triggers` | 非空字符串数组，至少 1 项 | 是 | 触发动作列表。`draw` 的 `trigger` 等于其中任一项时，本事件才参与本次抽取。 |
| `events[].probability` | 0 到 1 的数字 | 是 | 该事件的固定概率。`0` 永不命中，`1` 必定命中，0 和 1 都不消耗随机数。 |
| `events[].max_hits` | 非负整数或 `null` | 否 | 最多命中次数；`null` 或省略表示无限，`0` 表示从一开始就不再抽取。 |
| `events[].message` | 字符串 | 是 | 命中时随结果返回的文字，可以填空串。 |
| `events[].effects` | 任意 JSON 值 | 否 | 命中时原样返回（深拷贝），省略时结果为 `null`。 |
| `events[].` 其他字段 | — | — | 不允许；写错的字段会在装配时报配置错误。 |

配置在装配时做整体检查：`events` 不是数组、id 重复或为空、`triggers` 为空、概率越界、`max_hits` 为负数、`message` 不是字符串，都会直接报错，不会拖到第一次抽取才失败。

`example.json` 是一份可直接使用的示例：探索或休息时可能下雨（无限次），探索时还有小概率捡到一枚旧硬币（最多 1 次），赶路时必定遇到一次安静的路程（最多 2 次，第二次之后不再抽）。

## 内部操作：`draw`

由需要的组件通过 `backend.modules.call(节点ID, 'chance.events', 'draw', 参数)` 调用；参数与状态校验由宿主完成。

参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `trigger` | 非空字符串 | 是 | 触发动作名称，用来筛选 `triggers` 包含它的事件。 |
| `context` | 对象 | 否 | 调用方附带的上下文。组件接受并校验它是对象，但**不用它改变概率、上限或计数**，也不把内容写进状态。 |

返回：

```json
{
  "events": [
    {"id": "rain", "message": "天空落下细雨，路面渐渐湿了。", "effects": {"weather": "rain", "mood": -1}}
  ]
}
```

- `events` 只包含本次命中且未达到上限的事件，顺序与配置中的顺序一致；没有命中时是空数组。
- 每个元素固定为 `id`、`message`、`effects` 三个字段；`effects` 是配置值的深拷贝，调用方修改返回值不会影响组件配置。
- 组件不解释 `effects` 的含义，也不执行任何效果的落地。要改实体资源，请由调用方在收到结果后自行完成。

## 抽取规则

1. 先按 `trigger` 筛选：`triggers` 包含该动作的事件才是「适用事件」，其余事件本次不抽、计数不变。
2. 再看上限：该事件累计命中次数已达到 `max_hits` 时跳过；`max_hits` 为 `null` 时一直可抽。
3. 再独立判定：每个适用事件各做一次自己的伯努利判定（`random.random() < probability`），事件之间互不影响，也不受彼此或自己的历史命中次数影响。次数**不是**权重，也没有保底或补偿机制。
4. 命中才把该事件的计数加一并加入结果；未命中不写计数。

因此概率 `0` 稳定不命中、概率 `1` 稳定命中；同一个事件连续命中不会提高或降低后续概率。

## 状态与重启

`state` 只有一个 JSON 字段：

| 字段 | 说明 |
| --- | --- |
| `counts` | 事件 id 到累计命中次数的映射。只记录命中，未命中的事件不出现（等价于 0）。 |

状态随节点存档一起保存，重启后从原处继续，已经达到 `max_hits` 的事件不会因重启而重新获得次数。装配时会初始化缺失的 `counts`，并清理非字符串键、负数或非整数这类损坏计数。配置中移除某个事件后，它原有的计数会保留在状态里但不再参与抽取。

## 限制

- 只提供内部操作，没有 Agent 工具；需要给模型用时，请由另一个组件声明自己的工具并转调 `draw`，频道和权限也由那个组件声明。
- 不响应信号，不会自己定时抽取；每次抽取都必须由调用方显式调用。
- `context` 当前不参与判定，也不影响计数；如果要按上下文区分事件或分桶计数，需要另做组件或扩展本组件的配置契约。
- 计数按事件 id 全局累计，不按节点、角色或地点分桶；一个模块实例只有一份计数。
- 只使用标准库 `random`、`copy` 和宿主提供的 `datanet` 运行时，不访问网络、不执行 `eval`、不调用系统命令，不需要新增依赖。
