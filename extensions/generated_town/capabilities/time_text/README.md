# 时间文本（`time.text`）

把一个文本节点当作日历：每收到一个**新的**世界脉冲（频道 `world.tick`），时间往前走一格，并把当前时刻写成该节点的文本。重复送达的同一个信号（相同 `signal_id`）不会重复推进，也不会重写文本。

组件只管自己的状态和挂载的那个文本节点：不创建节点、不建立连接、不修改世界里的其他东西。信号的频道交集与强度由网络负责，组件不重新实现传播。

## 挂载

- 节点类型：`text_file`（文本节点）。
- 模块 ID：`time.text`，版本 `1.0.1`。
- 响应频道：`world.tick`。网络需要把脉冲经由 `world.tick` 频道送到这个节点，否则不会调用组件的 `on_signal`。
- 写入主键：`content`（每次覆盖为当前时刻文本）。

## 配置

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `slots` | 字符串数组，至少 1 项 | 是 | 一天的时刻表。数组长度就是一天几格，每个元素就是该时刻写入的文字。 |
| `format` | 非空字符串 | 是 | 写入文本的模板，可用 `{day}`（天数，从 1 开始）、`{slot}`（当前时刻文字）、`{tick}`（累计总时刻，从 -1 开始）。 |

`example.json` 的默认配置是一天五格「早上、中午、下午、傍晚、午夜」，文本为 `第{day}天-{slot}`，例如 `第2天-早上`。

改一天几格只改 `slots`；改文字也改 `slots`；改整句排版改 `format`。

`format` 会在装配时试渲染一次：引用了 `{day}`、`{slot}`、`{tick}` 之外的占位符（或写成 `{0}` 这类位置参数）会直接报错，不会拖到第一个脉冲才失败。`slots` 为空、元素为空串或 `format` 为空串都过不了配置校验。

## 时间怎么走

- 装配后是「尚未开始」：`tick = -1`，不写文本节点。
- 第一个新信号到达：`tick = 0`，第 1 天第 1 格（默认文本 `第1天-早上`）。之后每个新信号前进一格：`day = tick // len(slots) + 1`，`slot = slots[tick % len(slots)]`。
- 以默认五格为例：第 5 个信号是 `第1天-午夜`，第 6 个信号是 `第2天-早上`。
- 同一个 `signal_id` 再次到达：返回 `advanced=false`，`tick` 不变，文本不重写。内容相同但身份不同的信号是两个信号，会各走一格。
- 写入失败时抛错，`tick` 和 `last_signal_id` 都不推进，后续脉冲还能补上这一格。

## 内部操作

以下操作供其他可信组件调用（`backend.modules.call(节点ID, 'time.text', 操作名, {})`），不会自动变成 Agent 工具；参数校验与状态检查由宿主完成。

| 操作 | 参数 | 返回 |
| --- | --- | --- |
| `get_time` | `{}` | `{day, slot, slot_index, tick, text}` |
| `get_day` | `{}` | `{day}` |
| `get_tick` | `{}` | `{tick}` |

`slot_index` 从 `0` 开始，是本时刻在 `slots` 里的下标；`text` 是此刻应当写在文本节点上的字符串。三个操作都不改变状态。

「尚未开始」时三个操作返回：`tick = -1`、`day = 0`、`slot = ''`、`slot_index = -1`、`text = ''`。

## Agent 工具

没有声明工具（`tools` 为空）。读取时间请用上面的内部操作，由需要的组件自己去包装成工具，频道也由那个组件声明。

## 信号返回

`on_signal` 返回 `{advanced, day, slot, slot_index, tick, text}`，核心会把它记在该信号本次送达的结果里。`advanced` 表示这一次是否真的推进了一格。

## 状态与重启

`state` 只有两个 JSON 字段：

| 字段 | 说明 |
| --- | --- |
| `tick` | 累计推进的总时刻数，整数且 ≥ -1；`-1` 表示尚未开始，`0` 是第 1 天第一个时刻。 |
| `last_signal_id` | 最近计入的信号身份，用于去重。 |

状态随节点存档一起保存；重启后从存档恢复，时间从原处继续，并且在恢复后再次收到上一次计入的那个信号也不会重复推进。

## 限制

- 只响应 `world.tick` 频道。要换成别的脉冲频道，需要改清单里的 `signals` 并重新验证发布，不能靠配置切换。
- 只写挂载节点的 `content` 文本，不写别的键，也不创建任何节点。
- 依赖宿主自带的 `datanet` 运行时和 `jsonschema`，不需要新增依赖，也不访问网络或系统凭据。
