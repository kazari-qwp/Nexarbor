# entity.profile · 通用实体资料与物品

给任意节点挂一份“实体档案”：**资料字段（profile）**、**金币（coins）**、**物品数量（items）**。
状态随节点存档持久化；其他组件通过 operations 读取和修改；资料同时通过核心统一元数据接口
（`network.get_metadata(node_id)` 的 `extensions`）对外可见。

本组件只做“记录与原子修改”这一件事，不含商店、职业、移动、交易规则等业务，也不给 Agent
提供任何能改写自己资料/金币/物品的工具。

## 挂载

- 支持节点类型：`node`、`agent`、`text_file`、`pulse`（任意节点都能挂）。
- 依赖：无（`requires` 为空）。
- 同一节点只挂一个 `entity.profile` 实例；多个节点各挂一份互不影响。

```python
backend.modules.mount('npc/阿岚', 'entity.profile', {
    'profile': {'name': '阿岚', 'role': '旅人'},
    'coins': 24,
    'items': {'面包': 2, '火把': 1},
})
```

完整可运行示例见 `example.json`。

## config

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `profile` | object | `{}` | 初始资料字段，值是任意 JSON 值（字符串、数字、布尔、数组、对象）。 |
| `coins` | integer ≥ 0 | `0` | 初始金币。 |
| `items` | object：物品名 → integer ≥ 0 | `{}` | 初始物品数量。 |
| `metadata_namespace` | string | `"profile"` | 资料在核心元数据 `extensions` 下使用的命名空间；不能是空串或 `core`。 |

**初始化只补缺失状态**：`setup()` 用 `setdefault` 写入，节点已有存档状态时以存档为准，
因此重挂载、读档不会把进度重置成配置里的初始值。配置值本身非法（金币为负、物品数量为负、
资料不是 JSON）会让挂载直接失败。

## state

```json
{
  "profile": {"name": "阿岚", "role": "旅人"},
  "coins": 24,
  "items": {"面包": 2, "火把": 1}
}
```

- 三个键恒存在；`coins` 与每个物品数量都是 **≥ 0 的整数**。
- 数量减到 0 的物品会从 `items` 中移除，不保留 `0` 条目。
- 状态是普通 JSON 对象，符合 `state_schema`，可直接随宿主存档保存与恢复。

## operations（供可信组件调用）

只供组件间调用：`backend.modules.call(node_id, 'entity.profile', 操作名, 参数)`。
这些操作不会变成 Agent 工具，参数与结果由宿主按清单校验。

三个操作都返回**调用后的完整快照**：

```json
{"profile": {...}, "coins": 24, "items": {...}}
```

返回值是深拷贝，调用方修改它不会影响组件状态。

### `read`

参数：无。

读取资料、金币与物品。适合别的组件查询某节点的当前档案。

### `update_profile`

参数：

```json
{"fields": {"role": "铁匠", "mood": "平静"}}
```

按字段合并进 `profile`（未提到的字段保留原值）。值必须是 JSON 数据（对象键必须是字符串），
否则抛 `ValueError` 且不改动任何状态。

### `adjust`

参数（三者都可省略，至少给一个才有实际效果）：

```json
{"coins": -5, "items": {"面包": -1, "火把": 2}, "fields": {"mood": "疲倦"}}
```

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `coins` | integer | 金币增量，可为负。 |
| `items` | object：物品名 → integer | 物品数量增量，可为负；出现新物品名即新增库存。 |
| `fields` | object | 同时按字段合并资料。 |

这是**跨金币、物品、资料的单次原子修改**：先校验全部参数、算出全部新值并检查非负，
全部通过后才一次性写回；中途任何一项失败，金币、物品、资料都保持原样（不会“改一半”）。

失败示例：`{"coins": -5, "items": {"面包": -2}}` 在金币够、面包不够时抛
`ValueError`，金币不会先被扣掉。

## tools（Agent 可见）

| 名称 | 频道 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- | --- |
| `entity_view` | `access.read` | 无 | 同 `read` 的快照 | 只读：查看本节点的资料、金币与物品。 |

- 这是本组件唯一的 Agent 工具，只读，不提供任何增减金币、增删物品或改资料字段的工具。
- 频道由清单静态声明为 `access.read`：调用方需要能通过 `access.read` 频道的连接到达该节点；
  频道与强度由网络负责，组件不重复实现传播。
- 工具读的是**本节点**的档案，不能指定别的节点。

## signals

无（`signals` 为空）。本组件不响应信号，也不修改信号传播。

## 核心元数据

资料字段会以命名空间（默认 `profile`）出现在核心统一元数据里：

```python
backend.network.get_metadata('npc/阿岚')['extensions']['profile']
# {'name': '阿岚', 'role': '旅人'}
```

- 只发布 `profile`；`coins` 与 `items` 不进元数据（需要的话用 `read` 操作读取）。
- 资料为空对象时不发布该命名空间。
- 卸载组件（或实例关闭）时移除自己注册的元数据 provider，不影响其他节点上的实例。
- 命名空间由 `metadata_namespace` 决定；同一节点上若已有别的组件也用 `profile` 这个命名空间，
  把它们配置成不同的名字即可，核心会拒绝两个同名的扩展命名空间。

## 行为边界

- 不校验调用者身份、不判断“该不该给”：谁有权限调用是宿主与调用方的事；这里只保证金额与数量
  不为负、修改整体成功或整体不生效。
- 不做绝对赋值（没有“把金币设成 N”“把物品清空”的操作），只做有符号增减，避免绕过业务检查；
  初始值只来自 config 或已有存档。
- 不做商店、职业、移动、战斗等业务规则；需要时由其他组件组合这些操作实现。
