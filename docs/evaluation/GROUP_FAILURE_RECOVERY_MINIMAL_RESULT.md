# 成员退出隔离与原生 JSON 纠错最小验证

日期：2026-10-14。仅在模块化成品目录修改；基础 Python 框架和原始备份未改。

## 实现

- Harness 适配层独立 request-recovery 模块监听原生 agent/request-error。对工具参数非法 JSON 追加普通历史纠错消息，附可取得的工具名、参数原文和 JSON.parse 诊断。同一失败步骤最多两次纠正重试；不修写参数，不改原生循环，不将失败的工具调用执行或伪造为成功。
- 去中心化预设在原生致命错误时立即登记退出；委托 settled 作为补充。退出仅影响本轮，释放有效认领，保留节点、会话、记忆和工作目录；候选只等待剩余成员，最后一人可完成，全员退出才失败。单成员请求预算耗尽也隔离处理；共享时间预算或主动 stop 仍结束全组。
- 去中心化组退出人数达到初始人数一半时通知管理者一次。讨论组只计算普通成员：达到一半通知一次；普通成员全退出仍由 Leader/Recorder 完成，核心角色失败仍报告未完成。新任务重新启用成员，清空本轮退出记录和通知标记。
- 原始错误码和消息保留在退出原因、执行事件与报告中。

## 验证结果

1. test_group_failure_isolation.py：9/9，通过认领转交、个人文件保留、半数通知去重、只剩一人交付、审核者掉线收尾、全员失败、预算隔离、普通成员全部退出、新任务恢复、核心角色失败、原始错误保留和原生错误登记竞态。
2. native_request_recovery_test.cjs：4种情景通过——纠正成功、连续失败只重试两次、其他协议错误不重试、后续步骤重新获得纠正预算。实际 Harness 循环及历史消息；失败调用未执行，重试消息保留原始前缀并包含错误参数。
3. native_group_failure_test.cjs：实际 Harness 适配层 + 新编译 Python 后端通过。模拟模型中两位成员连续产生非法工具参数，各纠正两次后退出；认领释放，半数通知一次，剩余一名成员完成同一候选，最终完成通知一次，原始 MALFORMED_RESPONSE 保留。
4. 三项受影响回归通过：正常全员验收、候选否决/旧票/停止/恢复、两种组归档恢复保持历史内容。

原生联通测试首次发现“致命错误后、委托登记前收到同伴通知再次唤醒”的竞态，已通过即时退出登记及退出后 pre-step 阻止处理修复，修复后的同一最小场景通过。

模型响应在上述测试中为本地模拟，不使用付费 API；未重跑完整 hone 测试，未安装到用户正在运行的客户端。编译后端已同步到 adapters/harness/runtime/backend。
