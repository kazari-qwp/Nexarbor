# DataNet：把 Agent 组织成能交付的团队

DataNet 是一个模块化的 Agent 网络框架。它把独立上下文、工具能力、共享资料、任务委托、团队协作和持久化状态组合起来，让 Agent 根据任务组织团队、完成项目，并交付可核验的成果。

**灵活组网、模块拔插、持续优化和稳定交付，是当前最有说服力的四个特点。** 在同一个 hone 项目的六轮已完成固定网络测试中，从 0.3.10 到 0.3.16，每轮成果都通过了相同的 **12项库测试与6项CLI检查**。架构与通信机制持续变化，交付质量保持一致。

## 为什么这套架构值得继续做

### 组织可以随任务改变

网络预设可以快速搭建完整团队，讨论组与执行组的人数均可通过参数设置。根也可以直接创建 Agent、自主安排分工。拓扑、角色与工具能力可以分别组合，让不同任务采用合适的组织方式。

本次测试已经展示了两种实际组织：

- **固定网络**：5人讨论、2轮形成方案，再由4人去中心化执行、整合与共同验收。
- **自主组网**：根选择直接管理4名操作者，按核心库、CLI、测试、文档划分角色。

讨论组适合生成观点、澄清需求、制定方案；去中心化组适合在方案与接口确定后并行推进实现。二者可以衔接，也可以单独使用。随着预设增多，框架可以承载研发、研究、分析、评审等更多组织方式。

### 功能可以持续拔插和升级

Python 基础框架、业务组件与 Harness 适配层分开。工具、Skill、网络预设、工具箱、Agent 预设和节点都有独立组件入口，依赖与资源由清单声明，条件触发通过统一事件管理。

这种结构让能力扩展有明确的落点：增加一个工具箱、替换一套协作预设、调整某个角色的指南，均可以作为独立模块推进。新能力可以逐步接入，成熟模块也可以继续复用。基础框架与具体工作方法分离，为后续适配更多任务和宿主保留了空间。

详见[组件拆解表](../COMPONENT_MAP.md)与[框架及事件接口](../ARCHITECTURE.md)。

### 协作覆盖完整工程流程

去中心化组拥有任务认领、文件范围管理、个人 Git 工作树、提交整合、成果候选与共同验收。根负责组织和交接，成员可以自主认领并协商推进。成果有实际仓库、提交ID与报告路径，最终还通过独立测试验证。

Agent 的会话与记忆独立保存，网络状态、委托报告和工作成果可以落盘。异步委托与消息队列支持不同成员按自己的节奏工作。这些机制为持续项目、团队复用和长任务提供了基础。

最近两批测试中，固定网络均完成了“讨论→实现→整合→共同验收→返回根”的完整闭环，并通过全部外部检查。**多轮交付质量的一致性，是目前最值得强调的成果。**

### 模型能力之外，还有可积累的框架优化空间

缓存、上下文披露、轮次调度、消息协议、验收通知和终端生命周期，都可以由框架统一优化。这让改进能够作用于整个团队，并成为后续任务可复用的能力。

已记录的优化效果包括：

- 原生历史更新与按需披露后，输入缓存命中率由早期的 **74.33%** 提升至后续约 **97%～98.63%**。
- 未命中输入在一轮对比中从 **804万** 降至 **229万**，减少约 **71.5%**。
- 执行尾部块平均长度经历 **16,615→2,408→约24字符** 的精简，常驻内容只保留简短状态。
- 讨论提交回执由约 **47,610字符** 降至 **1,106字符**；写入回执由约 **48,287字符** 降至 **1,971字符**。
- 公共笔记限制为200字符，详细内容进入按需查询的输出板；最新测试讨论尾部最大 **222字符**，包含标识。
- 长命令最多同步等待10秒，再返回后台任务ID；提供查询与停止能力，命令硬限与本轮结束清理负责收尾。最新测试结束后，四组均未发现遗留终端进程。

这些数字来自不同版本与自主运行轨迹，体现各机制已经产生的实际效果。总体费用同时取决于 Agent 的实现、自测和重试行为，应与缓存指标分别观察。

### Token 与费用口径

谷价为每百万Token：缓存命中输入0.02元、未命中输入1元、输出4元。

```text
费用 = (命中输入 × 0.02 + 未命中输入 × 1 + 输出 × 4) / 1,000,000
```

第一批合计约 **¥6.74**，第二批合计约 **¥8.22**，两批合计约 **¥14.96**。这是模型usage的统一价格估算，不是账户账单核对。缓存输入也进入总Token，应分项计费。

各组原始Token、失败检查与审计证据见[第一批报告](HONE_THREE_ARM_RESULT.md)和[第二批报告](HONE_FOUR_ARM_OFFLINE_RESULT.md)。

## 未来潜力

DataNet 的扩展空间来自可组合的组织与可替换的组件。当前的讨论组、执行组与直接委托只是几种工作方式；同一基础可以继续发展出研究团队、审查团队、测试团队以及跨阶段项目流水线。

值得继续推进的方向：

- **更丰富的预设与角色**：按项目需求选择团队规模，组合规划、执行、评审与验收能力。
- **可视化网络操作**：图界面与缩略图帮助多模态Agent理解结构、选择节点并调整协作关系。
- **更长期的团队记忆**：基于当前持久化与同网络内复用机制，积累项目经验、接口约定和工作方法。
- **更广的模型与宿主适配**：沿着独立适配层接入更多执行环境，把已经成熟的业务组件继续复用。
- **更多真实项目基准**：用不同规模、不同领域的任务验证协作收益，发展适合各类任务的组织方式。

这些方向是后续规划，已有基础包括模块清单、网络预设、独立会话、持久状态、异步通信和工程协作流程。**框架每增加一个成熟组件，都可以让后续团队直接获得新的能力；这种可积累、可组合的成长方式，是DataNet长期潜力的重要来源。**
