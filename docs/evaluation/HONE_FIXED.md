# hone 固定组织端到端测试

执行日期：2026-10-13。使用独立 DeepSeek Harness 桌面客户端和 DataNet 0.3.6，通过后台接口启动全新根会话。

## 固定条件

- 根直接管理两个小组，先讨论再实现。
- 讨论组：Leader、Recorder、3名普通成员，共5人，讨论2轮。
- 去中心化组：4名平等成员，自主认领子任务、协商接口、实现、自测、提交、整合与共同验收。
- 根负责固定编排、交接和回收，成员承担实现工作。
- 模型配置沿用 thinking high、500k 上下文、50k 单次最大输出；以客户端实际请求记录核对。总时间预算30分钟，去中心化组采用30分钟时间预算、现有每成员100次请求上限；外部观察者在总时间到期时结束本轮。

## 输入与评分

固定上游 DevEval commit：`bb593c1f9c535ff0dde0c9f4807d58c9566c3a6c`。任务是依据 PRD、架构、接口与样例实现 CSV 转嵌套 JSON 的 Python 包和 CLI。软件架构是任务输入，Agent 的人数、层级和执行顺序则由本轮实验固定。

公开材料包含需求、架构、UML、CSV 样例、输入 schema 和调用示例；参考实现、评分测试及完整预期输出留在工作区外的评分目录。运行前固定材料和评分脚本哈希。

上游配置的测试命令与目录不一致，实际评分分别使用 unittest discover 加载 unit_tests 和 acceptance_tests，不改测试正文。参考实现通过7项单元测试、5项验收测试，共12/12；空实现产生导入错误，评分失败。

冻结交付代码后，将其 hone 包复制到独立评分目录，与上游测试和数据一起执行。分别记录通过、失败、错误、跳过和超时。CLI、自编测试和 README 的可运行性另行检查；上游这12项测试主要覆盖包接口，不能单独证明所有 CLI 需求达标。

## 观察与边界

观察人数及组织是否符合固定条件、独立会话和实际模型参数、有效认领、成员提交及整合、跨成员协商与验收、最终成果回根、质量、耗时及 token 用量。消息数量只作过程记录。

运行期间不替 Agent 完成业务工作、不提示算法或修补代码。确定由框架造成的卡壳可中断定位，保留原始失败记录；模型自身的实现错误由成员处理。组内宣布完成后仍须独立评分。全体通过、部分完成、失败和预算耗尽分别记录。

## 实际结果：框架权限问题导致中断

本轮通过真实桌面客户端后台接口运行，使用插件0.3.6。原生请求记录确认 reasoningEffort=high、contextWindow=500000、maxTokens=50000。已创建规定的5名讨论成员，第一轮3名成员提交发言；尚未完成两轮讨论，也未创建执行组。观察者发现组织和工具权限偏离固定条件后取消根及活跃成员，客户端接口确认所有相关会话停止。

Recorder和普通成员2共调用4次官方 `subagent`，启动4个额外官方子会话；这些子会话读取任务文件、运行终端和编写/验证算法原型。它们不属于固定的 DataNet 讨论组织，不能将其成果计为规定成员完成任务，也不能据此评价固定网络的多 Agent 能力。

已定位的权限边界：Harness 的 `tools.restrict` 过滤继承工具，保留 Agent 自己工具层的注册。官方 subagent 的按会话安装将工具注册到 Agent 自己的层；DataNet 的 `updateCapabilityTools` 又只将 `restrictableNames` 中的工具放入过滤器。执行权限检查的 `officialSeen` 只包含曾授予的官方工具，未授予但从自己的工具层出现的 subagent 没有被拒绝。源码位置为 `adapters/harness/framework/capabilities.js`、`adapters/harness/framework/tool-permissions.js`；本轮仅定位，未修改框架代码。

另有两个需要在重跑前处理的条件：

- 初次以 `hone-plan` 创建讨论网络触发 Windows `WinError 206`，存储路径过长。根自行缩短ID为 `dp` 后创建成功，这是恢复成功的框架错误。
- 根传给讨论组的项目查询文本包含需求摘要与文件路径，完整需求没有进入查询文本。无文件工具的 Leader 无法读取完整资料；Recorder及成员2则通过泄漏的官方子会话读取了资料。下次应在启动前把公开任务正文作为查询文本接入讨论组，保持默认讨论工具权限，使所有成员获取同样的输入。

独立评分没有运行于模型产物：没有完成并冻结的 hone 交付。12/12 仅属于参考实现的评分环境预检，空实现失败仅验证评分入口。本轮结论为“框架权限问题中断”，不是项目通过，也不是成员实现能力失败。保留已有原型作过程证据，不复用于下一轮交付。
