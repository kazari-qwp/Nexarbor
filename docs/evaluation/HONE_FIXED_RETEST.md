## 固定组织和运行入口

通过真实 DeepSeek Harness 桌面客户端后台接口运行。根直接创建5人讨论组（Leader、Recorder、3名普通成员，2轮）和4人去中心化组，先讨论后实现。成员自主认领工作。模型为 deepseek-chat，thinking high、500k配置上下文、50k单次最大输出；每轮总观察上限30分钟，执行组自身预算30分钟。

完整公开资料在启动前通过成品后端写入 root/project 查询文本。讨论组引用该节点，执行组读取相同公开材料。参考实现和评分测试位于工作区外，固定上游 commit 为 bb593c1f9c535ff0dde0c9f4807d58c9566c3a6c。

## 修复

- Harness适配：ToolPermissions 对未授权工具实行执行拒绝，覆盖 Agent 自己的工具层及后来注册的工具。AgentLoop 的 agent/tool-schemas waterfall 过滤未授权的原生模型工具定义；已授权并加载过的定义在停用后继续保留，执行权限变化仍由工具权限消息说明。
- Python框架存储：统一 Windows 扩展路径入口，报告组件共用该入口。超长路径的网络资源、检查点保存恢复已验证。
- 去中心化组件：新工作区采用较短路径，Git开启仓库级 core.longpaths；实际工作区位置存入小组状态，成员和根收到一致路径，已有工作区按原位置恢复。
- 网络预设：内部成员的创建由网络创建权限授权，不再要求调用者同时获得通用 Agent 创建权限。讨论和去中心化两个组件分别实现，未写入基础框架的业务分支。
- Harness通信：运行节点的反向RPC等待覆盖节点实际配置的超时及清理余量，避免固定十分钟等待提前结束仍在预算内的节点循环。
