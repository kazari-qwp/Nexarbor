# 客户端组件工作室

当前使用 `nexarbor-module/v3` 固定异步入口，网络配置为 v8。未指定路径时使用 `build/workbench-v3`；本机桌面快捷方式已绑定独立的 `build/studio/workbench-v3`。旧小镇、旧应用、旧发布组件和旧测试预设尚未迁移，未添加兼容层。

1. 打开 Nexarbor 桌面工作台。节点“工具”页可从本机 Harness 官方目录添加工具，设置提供频道；应用网络后生效。
2. Agent 属性中启用 Harness 执行器，设置 strength 和 channels。Agent 沿连接调用 `network_visit`，取得可达节点提供的工具；每次执行会重新检查权限。
3. 在模块栏当前目录点击“制作新模块”，选择“从空白制作组件”或“标准 v3 组件”。使用 CodeMirror 查看、编辑源码和差异。
4. 连接已运行的 Harness 后，可将需求交给组件制作 Agent；它使用原生会话和编码工具，会话可在 Harness 列表中查看。也可以手工修改组件。
5. 验证在独立 Python 子进程运行，有时间和输出上限；校验清单、固定入口、挂载、信号响应、状态和组件自带测试。
6. 通过后才可发布，发布内容必须与已通过验证的源码摘要一致。修改代码后必须重新验证。发布版本只读，可以建立修改副本。
7. 选择节点并装配。示例的 state/access 会保留；主界面的模块页可以查看配置、网络访问授权和状态。清单 requires 中的依赖递归补齐，已装实例复用并保留配置、状态及授权。组件之间通过公开操作复用，不拿其他实例引用。

制作会话支持继续或分叉历史；指南前缀变化时应开新会话。固定入口和本地 API 见 [组件说明](LOCAL_MODULES.md) 与 [制作指南](../extensions/development/capabilities/component_studio/resources/MODULE_GUIDE.md)。

制作 Agent 的职责、核心 API 和页面协议统一使用中文说明，保留代码标识和协议字段。每次开始制作时工作副本刷新三份当前规范；规范或依赖接口变更后，旧历史不能继续或分叉。测试文件必须由 unittest 实际收集运行，零项收集不会被当成业务验证通过。

## 组件源码和制作资料

“组件文件”只显示组件自身的 Python、清单、示例、测试、说明和页面。宿主的 `AGENTS.md`、制作规范和依赖参考在“制作资料”中只读显示，不混在新组件源码列表内；制作 Agent 仍可直接读取这些文件。目录按层级折叠，行内只显示文件名。

工作副本右侧垃圾桶用于删除工作副本，编辑区“删除文件”用于删除当前可选文件，都会先确认并归档到当前工作区的 `studio/trash`。已发布组件不随工作副本删除；`module.py`、`module.json`、`example.json` 和制作资料受到保护。运行中的制作／验证任务和过期的编辑内容会阻止删除。

## 连接、书签与快捷键

选中节点后，“属性”或“连接”页的“新增连接”按钮打开方向、频道、门槛和倍率设置。“连接”页列出本节点出边与入边，出边可删除；默认右键从一个节点拖到另一个节点也能打开连线设置。

默认操作如下；左上角“设置”菜单悬停或点击展开后，选择“自定义快捷键”，可以修改这些键盘及鼠标组合，并保存到当前工作区。文本框和源码编辑器保留文本编辑的撤销行为。

| 操作 | 默认快捷键 |
| --- | --- |
| 复制内部子网／保留外联子网 | A／B |
| 删除悬停书签 | A 或 B，可单独指定 |
| 保存悬停网络书签至网络预设 | S |
| 保存网络草稿／删除选中元素 | Ctrl+S／Delete |
| 撤销／重做 | Ctrl+Z／Ctrl+Y |
| 累加或取消点选节点、边 | Shift+点击 |
| 扩大／缩小选区 | Shift+滚轮向上／向下 |
| 节点间拖动连线 | 右键拖动 |
| 重命名悬停书签 | 中键 |

撤销／重做只记录网络和布局修改。书签新增、删除、重命名、分类和选区变化不进入撤销队列，也不清空已有重做记录；拖入书签生成网络仍然可以撤销。鼠标停在书签卡片位置连续按删除键，会依次删除该位置补位后的书签，无需移走再移回来。

选区按“节点—边—节点”每次扩缩一层。A 复制选中节点并只保留内部出边，B 保留所有出边。仅选边时，两种模式都不保存起点；A 只保留边参数，B 额外保留终点。纯边书签拖到节点上将该节点作为新起点，缺失端点时由连接弹窗补齐。

从书签、历史或左侧资源栏拖入画布，每次都分配并检查新节点编号，名称保持原样，不添加“副本”。A/B 内部链接均重映射到本次新节点，模块配置及状态中声明为 `node-id` 的内部引用也会重映射；A 不保留外联，B 外联仍指向原来的外部节点，落点网络不存在该目标时才清除。副本使用独立的文档目录，不复用原生 Agent 会话。两种背景色区分模式，复杂子网显示缩略图，名称仅悬停显示。相同选区连续按同一复制键两次取消刚建的书签；A、B 各按一次分别建立两份书签。

书签支持 A 子网、B 子网、单点、纯边四类筛选；新建书签进入当前自定义分类。书签区和历史区宽度约为 3:1，默认使用 48×40 的纯图卡片：单点为小圆圈、纯边为线段、网络为缩略图，悬停只提示名称。书签区右上角按钮同时切换两区的纯图／原文字视图；纯图按可用空间分页，文字视图每页 6 项。

历史区保留最近 100 个实际创建或使用的配置。每条历史都有独立节点／网络／文档／布局或边缓存，复用时始终读取缓存，删除原节点、书签或网络预设不会使缓存失效。单击可在右侧查看缓存，悬停按 A/B 可保存成书签，也能直接拖入画布；纯边的新起点由落点决定。历史按配置去重，不比较实例编号、位置、上下文游标或模块运行状态；模块配置、访问授权、文档内容、网络结构与外联目标仍参与比较。使用配置 1、2、1 后，历史为 1、2；整个网络放置只记录整体配置，不为每个内部节点额外刷记录。添加、删除、重命名书签、整理目录或切换视图不改变历史顺序。书签、历史、分类、预设、视图和侧栏设置保存在当前工作区的 `editor-library.json`；画布修改需保存草稿，点击“应用网络”才改变运行网络。

文档、组件、导入导出、保存应用、视角切换及布局按钮统一放在紧凑的单行顶栏。窗口较窄时，布局操作区支持横向滚动。左右侧栏的标题旁有折叠箭头，收起后保留 32 像素展开栏。右侧工作区在没有选中节点和边时自动收起，选中后展开；手动折叠／展开只覆盖当前选择，改变选择后恢复自动规则。仅剩根节点时仍正常显示节点。

节点保持圆形，悬停时不再出现方形预览。名称下方在悬停或选中时显示两组小按钮：工具图标加当前提供工具数、模块图标加已装模块数。每组图标与数字属于同一个按钮，点击任一部分直接选中该节点并打开右侧“工具”或“模块”页，不触发 Agent 对话或改变节点位置。

模块和工具资源行右侧也显示两组图标数字：携带工具与依赖模块，只计直接声明，不递归统计。点击可展开相应清单。模块携带的 Agent 工具也出现在工具栏；拖工具会带入实现模块及依赖，拖模块会提供其工具，节点内去重。派生工具显示在节点“工具”页，通过卸载实现模块移除，不另存一份重复 offer。未进场的节点模板采用相同装配规则；仍被依赖的模块不能单独卸载。

标准库中文名称为“工具收集器”“模块流程执行器”。新增“移动到此”携带移动工具并依赖“位置资料”；目的地装前者，NPC 与旧地点需有后者和初始位置连接。可导入 [三节点演示网络](../examples/move_here/network.json)，按 [演示说明](../examples/move_here/README.md) 取得和调用移动工具。业务按顺序 await，节点锁负责多节点隔离、提交与异常回滚，无需装配流程执行器。

运行控制固定在左侧栏底部，分成两行：第一行是进度状态和脉冲选择，第二行是单步、运行／暂停、时刻数。上方组件和筛选内容单独滚动；收起左侧栏时一起隐藏，展开后恢复。画布和右侧工作区一直延伸到状态栏上方，不再为运行区占用整行底部空间。

## 模块自己的配置页面

组件可在清单中声明 `"frontend":{"entry":"ui.html","title":"元数据字段","height":460}`。页面作为组件源码的一部分验证、发布、导出，修改后必须重新验证。当前使用自包含 HTML，脚本和样式放在页面内；没有页面的组件继续使用 JSON Schema 通用表单。

选择节点，进入“模块”，展开模块即可使用它的页面，也可切换到通用表单。页面通过 `NexarborModule` 获得本模块配置和状态的副本，提交的新配置经过 Schema 校验后进入网络草稿，点击“应用网络”生效。它不能调用任意后端 RPC、修改网络授权或读取其他模块。iframe 使用独立来源沙箱，宿主令牌不会交给页面。

组件工作室支持编辑 `.html/.css/.js`，并提供“页面预览”；发布版本仍只读。详细接口和中文界面要求见 [页面开发规范](../extensions/development/capabilities/component_studio/resources/FRONTEND_GUIDE.md)。

开发组件库附带由真实制作 Agent 编写的 [metadata.fields](../extensions/module_frontend_demo/capabilities/metadata_fields/README.md)：点击“＋ 添加元数据”增加名称、类型和值，支持删除字段，以及字符串、数字、布尔、对象、数组和空值。字段在 `read` 操作或 `metadata.refresh` 信号执行时发布到本节点的模块元数据命名空间。Python 与 HTML 均原样导出，来源摘要见组件内 `provenance.json`。

## 本机 Harness 安装路径

工作室优先使用 `DATANET_HARNESS_EXE` 环境变量；其次读取项目本地、未入库的 `build/harness-installation.json`，格式为 `{"executable":"E:/dsh/Harness/DeepSeek Harness.exe"}`；都没有时采用 Windows 默认安装目录。SDK 从所选程序自身的安装目录加载，避免新版程序混用旧 SDK。测试客户端使用独立 `DSH_HOME` 和界面数据目录，临时文件保存在项目的 E 盘 build 下，不改日常客户端或全局 TEMP/TMP。

“整理当前视图”只根据当前可见节点和连线整理布局；“整理选中”用于选定部分。筛选和普通拖动不会自动触发全图整理。

## 统一资源栏与配置书签

左侧“基础节点栏”“工具栏”“模块栏”“网络预设栏”默认折叠，共用资源管理器式浏览：顶部是返回、前进、上一级和可点击的面包屑路径，下面只显示当前文件夹的下一层文件夹和资源。双击文件夹进入，单击资源打开右侧详情；拖动才放入画布或装配节点。右键菜单支持新建文件夹、重命名、剪切、粘贴；默认快捷键为 Ctrl+Shift+N、F2、Ctrl+X、Ctrl+V，可在设置中修改。目录层级、资源别名只保存在当前工作区的 `editor-library.json`，不移动源码或工具文件。

基础节点可在右侧编辑名称、参数、文档以及待装配模块／工具，然后 Save 保存配置书签，全程不创建运行节点。网络预设可以查看和编辑其中各节点，再保存书签；拖入时添加到现有网络，不替换整张网络。悬停包含多个节点的书签按 S，或右键选择“保存”，将其原始 A/B 快照写入真实网络文件，分类仍为当前浏览的虚拟目录；右键“删除”只删除该书签。预设与原书签、使用历史独立保存。

网络预设和完整网络使用同一种 `{network, files}` 文档，`network.version` 为 8，关联文档内容也在文件内。真实存储位置由保存时的虚拟分类决定：在系统分类“已存储网络”及其子目录保存，写入当前工作区 `network_presets/networks/`；在其他分类保存，写入 `network_presets/fragments/`。网络预设栏的“保存全网”将当前整张草稿网络写入前一个真实目录，并归到“已存储网络”。也可选中全网制作书签，在“已存储网络”按 S 达到同样效果。完整网络同样能拖入已有画布当零件使用。

网络内容写在独立 `.json` 文件，复制方式、名称、布局等编辑资料写在相邻的 `.editor.json`；虚拟目录和别名仍只是客户端分类，不因剪切粘贴去搬文件。打开预设详情可查看磁盘路径；重新扫描从真实文件恢复资源目录，不依赖 `editor-library.json` 内缓存的预设正文。“已存储网络”是系统分类，不能删除、移动或重命名，其内部可新建自定义目录。

模块资源栏的每一级目录都有“制作新模块”，点击直接打开空白模块工作副本。工作副本记录发起目录，发布成品默认进入那里；重新打开客户端后仍有效，目录被删除则回到模块根目录。后续人工分类优先，不会因重复发布被搬回。顶部保留小型组件工作室入口，左侧大型入口已移除。

资源目录用 Ctrl 点击累加／取消选择，Ctrl+A 全选当前层级的文件夹与资源；可批量剪切、粘贴，拖选中的资源到节点。选中文件夹一起拖入时取其未归档资源，包含子目录并去重；整批装配只形成一次网络撤销，任一项不支持目标节点时整批不写入。普通剪切保留文件夹层级；文件夹右键“剪切目录内全部资源”只剪切其中全部资源（含子目录和归档项），在目标目录粘贴时集中放到当前层级。右键“删除文件夹”或 Delete 删除空目录；目录及子目录还有资源时由服务端拒绝。空目录树一起移除。

资源行右侧有归档图标，右键也可归档选中资源，Delete 对纯资源选择执行归档。原生菜单在“视图”右侧提供“归档”入口；浏览器可用“设置 → 资源归档”。归档页可按四类资源筛选、搜索、恢复。工具／模块归档隐藏相应资源书签和历史展示，但保留原配置和顺序，恢复后重新显示；已挂载实例继续运行。基础节点模板不可彻底删除；网络预设归档保留文件，确认彻底删除后只删除其网络文件和相邻编辑资料，独立书签和历史缓存保留。

官方 Harness 工具的彻底删除按钮禁用。自有模块删除前显示实际发布目录与文件清单，运行实例、未应用的已保存草稿、当前编辑网络、其他模块依赖、网络书签仍引用时拒绝。用户确认后只删除当前工作区 `studio/releases/<模块编号>` 下的发布文件，保留独立工作副本、其他工作区与共享项目源码；并清理该资源的独立书签／历史及撤销快照里的失效引用。删除记录阻止标准模块在重启时自动重新安装。重新验证发布同编号组件可再次安装。当前统一工具目录仍是 Harness 官方工具；以后自制工具接入时沿用目录及归属检查接口，本轮没有新增工具执行协议。

资源栏中的模块未挂载到节点时也能使用自己的配置页面，或者 JSON Schema 通用表单。填写后点击“Save · 保存至书签”，保存模块引用、配置、默认状态与访问授权；工具保存引用和提供频道。保存到当前书签分类，不执行组件，不改变当前网络。点击已有资源书签可继续编辑并保存同一书签。已挂载模块和工具的条目顶部也提供保存至书签、垃圾桶两个图标；垃圾桶只从当前节点卸载，不删除资源文件。模块书签保存当前配置与授权，新实例使用默认状态；覆盖已挂载模块时保留该节点的运行状态。

从资源栏、书签或历史拖工具／模块到节点，装配进入网络草稿，可撤销；点击“应用网络”才影响运行网络。重复装配相同工具引用时更新频道，不重复添加。实际装配才记录使用历史；保存、重命名、整理资源目录不改变历史顺序，也不进入网络撤销队列。

书签与历史均可筛选单节点、单边、网络、工具、模块；书签还保留 A/B 复制筛选。工具采用蓝色背景、模块采用金色背景，悬停显示“名称：描述”，中键可重命名。模块可在清单顶层提供可选的 `preview` 自包含图片，书签和历史有图显示图片，无图或图片失效显示名称。具体格式见 [页面开发规范](../extensions/development/capabilities/component_studio/resources/FRONTEND_GUIDE.md)。预览图只从当前模块目录读取展示信息，不为每条历史重复存储图片。

左右侧栏与画布相邻的边缘可拖动调整宽度，宽度按工作区持久化；保留折叠功能，窗口变窄时为画布保留空间。最大化、还原及窗口缩放会同步缩放画布视口，保留查看中心及节点坐标，不触发重新布局。小地图内外尺寸一致，固定在画布右下角，随可见图和视口更新。

外部工具与节点组件分开。当前适配的是官方文件、搜索、PowerShell 和后台任务服务，共十个工具；目录和工具测试不需要模型密钥。真实 Agent 对话与组件制作仍使用用户连接的 Harness。通用 MCP/Skill 导入和旧应用迁移以后处理。

验证子进程和模块接口边界不等于恶意代码沙箱。组件源码按可信本地代码运行，外部工具按宿主权限执行。

本轮实际桌面测试已走通：选择官方工具、应用、访问取得、调用读取、断开后拒绝、v3 模块验证／发布／挂载，以及重启恢复。没有付费模型调用。旧小镇的历史测试记录继续保留，但不代表它已在当前协议下复测。


## 项目目录、Git 和咨询工作流

直接启动且未指定项目时，首页显示“打开项目文件夹”和“新建项目文件夹”，不会启动网络后端。新建项目初始化 Git、首个提交、资源目录和“打开项目.cmd”。这两个入口也在顶部“工作台”菜单中；在含 nexarbor.json 的目录直接启动客户端也会识别该项目。

一个打开的文件夹就是一个项目。桌面菜单“工作台 → 打开项目文件夹”，或 `Nexarbor Workbench.exe --project <目录>` 可以打开；原有 `--workspace` 入口继续兼容。已有项目先亮窗口，再恢复画布，不会启动日常 Harness 窗口。

- `nexarbor.json`：资源索引和当前网络入口。
- `modules/`、`tools/`：下载的模块源码与工具声明。箭头下载只带选中资源及递归依赖；模块携带的工具也登记在项目中。官方工具保存调用声明，不复制宿主实现。
- `network_presets/`、`node_presets/`：项目网络／节点预设；虚拟目录仍由 `editor-library.json` 管理。
- `networks/`：按节点和受管理数据文件拆开的网络快照。
- `.nexarbor/contexts/`、`.nexarbor/conversations/`：上下文位置、分块日志及咨询记录。
- `.nexarbor/runs/`：本地执行缓存，Git忽略；账户授权也不进入提交。

顶部 **Commit** 真正推进当前 Git 分支：记录编辑图、布局、数据、模块源码与 Agent 日志前缀。“校验并更新网络”另外负责装配到运行网络。自动保存仅用于恢复未提交页面，不代替 Commit。项目记录允许从旧提交建立恢复分支；会先提交当前编辑，不重写旧历史。没有内置终端；需要命令行时，在项目文件夹打开系统终端。外部改变 HEAD 后须重新打开项目，客户端拒绝向过期版本提交。

资源列表右键可咨询模块／工具 Agent 或网络 Agent；节点工作台里挂载的模块／工具也有相同入口，悬停显示“名称：描述”。画布选中内容右键“咨询 Agent”打开可拖动、缩放的咨询窗。每轮固定全网、选中对象、配置和当时源码；模型按需读取，不能执行、修改或发布。回答须区分源码事实与推断。

需要改动时点击“建立修改分支”。源码有真实 Git 分支，新模块使用独立 ID，来源版本、问题和回答保留，旧节点仍使用原实现。制作过程只能操作工作分支，验证和发布仍是显式步骤。普通咨询不会暗中进入制作。克隆项目会带上已 Commit 的咨询快照和上下文前缀；原生会话在新项目导入为独立分支。

工作室以中央对话为主。左侧资源分组可折叠；源码默认折叠在最右侧，展开后压缩对话区，边界可拖动调整并记住宽度。支持网址、文件地址、图片粘贴／拖放和文本附件。网址可在外部浏览器打开，项目内文件地址可在资源管理器定位；图片使用原生 SDK 附件服务，能否识别由模型能力决定。


项目运行直接读取 `modules/<模块ID>/` 的源码和前端，同名后端组件不会覆盖本地版本。缺失本地模块时保留原配置并在节点显示感叹号，不借用后端同名实现替代。下载箭头可补齐资源和递归依赖；已有项目缺失的源码不会在 Commit 时被同名后端版本覆盖。资源栏默认只显示本地项目，切换来源后可选择后端可下载资源。工具实现随所属模块保存；官方宿主工具仅保存引用声明，客户端安装仍提供其执行端口。制作环境另建独立副本，不修改项目源码。

原按钮排的打开文件夹和设置入口已移除。顶部原生“设置”菜单包含自定义快捷键和资源归档；按钮排的“Agent”下拉包含“组件/模块制作agent”和“网络预设制作agent”。通用配置表单的添加、上移、下移、复制、删除和清空按钮使用 SVG 图标，支持键盘焦点并区分禁用状态。

画布选区右键可咨询、删除，或以 A/B 两种方式加入书签；轻点右键保留选区，右键拖动仍创建连接。保存的节点或网络若只有一条无起点入边，拖到已有节点时会将它接到新副本的相对终点；判定仅看快照结构，与选择和保存顺序无关。多条无起点入边不连接。纯边书签缺少终点时，拖到起点节点后用鼠标选择终点；点击空白或 Esc 取消，取消不产生编辑或使用历史。B 型纯边若保留了仍存在的终点则直接连接。


启动以可读网络配置为基础。模块缺失、依赖缺失、模块代码或配置错误只让相应模块不可用；节点保留 config/state/access、链接和数据，其他健康模块仍可执行。感叹号悬停显示原因，点击进入模块页；补回源码后“校验并更新网络”恢复装配。制作副本验证仍保持严格，不把不完整组件当作通过验证的成品。

运行缓存损坏但项目保存的网络可读时，在独立运行目录载入已保存网络，客户端顶部显示简略原因；原运行目录保留。上次打开位置的记录损坏时先保留原文件，再恢复项目入口。只有项目清单或网络确实无法读取时才回到“打开／新建项目”初始页，并显示简略原因；完整诊断在客户端用户数据目录的 `last-project-error.json`，不会再用阻塞报错窗口留下空白页。


角色场景查询采用渐进提供信息：查看处境只返回当前时间、位置、个人记录、同地人物和直接出口；查询地点取得公开用途；查询地图才生成实际道路图。地图不再作为固定文字背景逐轮注入，也不计算导航。时钟仍经 prepare → update_inputs.tail → agent/request-tail 在每次模型请求末尾刷新。

工具可以返回 `{format:"nexarbor-tool-content/v1",content:[{type:"text",text:"说明"},{type:"image",name:"图.png",mediaType:"image/png",data:"base64"}]}`。适配器先登记原生附件，再发送图片内容块；普通 JSON 工具结果保持原样。不要把文件路径或 base64 文字伪装成模型已看到的图片。图片随网络上下文的 Commit、导入导出一起保存，内容相同的附件只存一份。
