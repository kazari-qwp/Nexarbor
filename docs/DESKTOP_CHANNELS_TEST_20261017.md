# 桌面客户端与统一频道验证

日期：2026-10-17。开始前工作区干净，基线提交 b3b4af1；备份分支 backup/pre-desktop-channels-20261017 指向该提交。本次只在本地提交，未 push。

## 交付

- Windows x64 Electron 桌面客户端：`build/desktop/Nexarbor Workbench-win32-x64/Nexarbor Workbench.exe`。官方 Electron 44.9.0 下载经同版本官方 SHA256 校验；打包复用 @electron/packager 20.3.0。无需在使用时运行前端编译器，后端仍由 Harness 托管。
- Harness 会话顶部按钮启动客户端；命令行通过连接记录启动。打包程序实际运行后验证 contextIsolation、sandbox、webSecurity 开启、nodeIntegration 关闭，Renderer 无 require，令牌读取后移除 URL 片段。
- 拖动时保留线路主干，只调整端点附近的正交段；暂停拖动等待也不会切换临时线路。松手后 Worker 重算。固定圆形尺寸避免选择时重新测量隐藏，恢复双击对话。
- 连接统一 interfaces，格式 v6。工具发现和调用采用目标声明的 access_channels；调用者不能用任意频道绕过授权。三个应用的源码组件和预设已同步，不读取旧 v3/v4/v5 存档。
- 讨论公共笔记是普通文本，由 node_write 更新；轮初快照由讨论组件提供。不恢复 resident_text/write_resident_text 特例。知识库组织节点不消耗访问强度；修复零强度多走一跳的问题后仍保留实际集合可达范围。

## 验证结果

Python 测试按文件隔离组件注册表运行，修复失败后重跑对应文件；共 39 个文件、223 项，其中 219 项通过、4 项按条件跳过，最终无失败。跳过项保留原测试条件，包含独立二进制测试入口；未把旧打包后端当作新版验证结果。

覆盖核心信号、增量/完整存档及中断恢复、频道授权与嵌套权限、模块执行、上下文装配、第一应用讨论/执行组与生命周期、知识库检索和助手、NPC 并行/生育/事件/行动值，以及 Windows 长路径存储。测试辅助端口已同步正常完成标记、异步输入和核心提交通知，独立加载测试显式选择组件，避免依赖测试导入顺序。

- 前端 10 项 Node 测试通过；桌面连接边界 1 项通过。
- 真实指针测试通过：圆形与悬停、持续拖动、移动障碍后重新绕线、全关筛选为空、单击关闭一类、选中整理、筛选不改布局/线路/视角、新显示元素置顶与撤销。
- 原生 Harness + Mock：从空草稿经界面创建两个地点、两个居民与道路，权限视角、并行活动、脉冲回源、行动预算、移动、对话读写、完整存档和恢复分支通过。全部6个原生会话（含恢复分支）可在 Harness 左侧列表读取。
- 打包 Electron：实际打开同一运行网络，验证菜单、隔离配置、过滤、双击原生对话历史和持续拖动。
- Harness 官方会话按钮：未认证请求拒绝；已认证按钮实际返回桌面启动成功，启动真实客户端。
- 原生 AgentRegistry 创建/拆接/恢复与适配器配置保留测试通过。

以上真实模型 API 调用为 **0**，费用 **0**。Mock 验证的是代码、SDK、权限和交互路径，不作为模型自主决策质量评测。只关闭核实属于旧工作台测试目录的客户端；未操作用户个人客户端。

原始记录保存在 `build/desktop-regression-final.json`、`build/desktop-regression/`、`build/desktop-channels-20261017/` 与对应修复日志。build 不进入 Git。
