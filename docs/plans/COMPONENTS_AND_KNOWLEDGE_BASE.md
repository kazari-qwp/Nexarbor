# 组件化与知识库实施规划

这是本次工作的持久规划。先完成 A，再完成 B；进度、验证和决定记录在同目录 WORK_LOG.md。原备份目录不修改。业务代码留在 capabilities，普通 Agent、文本、图、权限、持久化、执行器契约仍属于核心。不得因加载依赖向 Agent 自动增加工具权限。不保留旧兼容入口。

## A：按组件装配第一应用

目标：包是分发单位，组件是加载单位，应用是组件选择、配置和网络预设的组合。框架发现组件、求依赖闭包并按拓扑顺序装配；同一组件只装配一次。组件以独立职责和可测试接口为边界，不把每个函数拆成组件。

1. 盘点现有组件、代码调用及资源引用，将可复用存储、Agent 装配、委托、消息、报告、终端、文本交付等从第一应用中提取。讨论与协作业务留在各自组件。角色和预设保留配置与文档。
2. 核心提供多来源组件目录、唯一 ID、显式依赖、确定性排序、缺失/循环/版本冲突报告和选择配置。只导入选中的组件及其依赖，不导入整包。不加载应用时保持纯核心。
3. 统一 Python 服务、节点 codec、运行时、工具绑定、原生扩展的装配来源。资源路径属于实际组件。组件依赖与 Agent 工具授权分开。
4. 停用依赖时阻止或显式级联停用使用者；工具执行权限同步撤销，数据保留。持久状态恢复时缺少组件需明确报错。
5. 第一应用由清单重新组合；两个应用共用组件只有一份源码。验证原讨论、协作、消息、权限、上下文和持久化路径。

## B：知识库扩展应用

目标：既可存资料，也可作应用记忆。固定入口、目录、原始资料区、数据区，以及两个按需工作的 Agent（归档、检索）。数据节点增加不增加 Agent。

### 结构与四类数据

- CSV：简单、少更新、需要整表交换的结构化数据；主键/过滤/分页/导出。
- SQLite：频繁更新、约束、关联与统计；索引/筛选/受控关联聚合。
- RAG：长文档原文加增量索引；关键词与语义检索，再取完整原文。
- Agent Wiki：概念、经验、决策和长期记忆；Markdown 页面、来源引用、页面链接及版本。

RAG 是索引方式；原始资料仍保存。一个来源可有主存储及派生索引/Wiki，但不无条件复制四份。原始事实与 Agent 整理结果区分，派生内容保留来源和版本。

### Agent 与接口

- 归档 Agent 判断用途、复用集合或设计字段与分类，使用一个受限的知识节点创建工具。仅能从四种类型创建节点，不获得任意组网、创建 Agent 或终端权限。路径、ID、建表、接线和默认模型配置由程序完成。
- 检索 Agent 处理复杂自然语言查询及跨集合综合。已知 ID、结构化筛选、关键词/向量查询直接执行，普通读写不经过模型。
- 输入内容/文件即可；用途、目标集合可选。接口覆盖 store/search/fetch/update/delete/export，结果包含稳定 ID、节点 ID、来源、版本及读取位置；大结果分页。
- 指南按需进入历史，不把资料库或完整目录放入尾部块。

### 写入与读取

1. 保存输入并登记来源、内容 hash、稳定 ID 和版本。
2. 优先用明确目标和已有规则；确需判断才调用归档 Agent。
3. 确定主存储、节点及结构，提交数据和目录，返回可读取的 ID。
4. 增量维护索引、Wiki，处理重复输入、版本变化、删除与派生失效。跨文件/数据库写入有可恢复状态；索引失败不冒充成功。
5. ID 和条件直接查询；关键词和语义结果按集合范围检索并融合。结果能追溯和完整取回。语义配置不可用时明确报告，不把关键词伪装成语义检索。
6. 索引懒加载/缓存、共享嵌入模型、批量导入；测冷启动与热查询 p50/p95、索引耗时、Agent 调用次数，按实际瓶颈优化。

### 复用与新增

复用核心与抽出的 CSV、SQLite、LlamaIndex、普通文本、Agent 装配等组件。新增知识目录、统一存储/读取、受限节点创建、归档策略、复杂检索和 Wiki 维护。知识库不依赖整个第一应用。

### 执行与验收顺序

1. A：组件目录/依赖/拆分与第一应用回归。
2. B1：固定网络、目录、四类数据读写及恢复。
3. B2：归档 Agent 自动选型、分类和节点创建。
4. B3：复杂检索、Wiki 及来源和版本同步。
5. 最小测试：四类存储、自动归档、完整取回、重复/更新/删除、重启、组件独立/共存、权限、查询不调用模型。分项验证后做混合资料验收。

给 Agent 的描述须短，指南从使用者视角编写；完成时提供改动文档的路径及工具描述原文。测试不启动整套历史付费工程项目。

## 用户后续指令（优先于前述实现细节）

- 所有扩展功能优先复用现有开源实现；只有核心框架由本项目自行实现。先评估已有方案，再做最薄组件适配。不要为体现功能完整而自行重造 Wiki、检索、数据存储、维护流程等。
- 页面维护、来源跟踪、过期知识处理等若需要本项目适配，独立包装成可复用能力；避免耦合到知识库或核心。
- 五小时额度剩余低于 8% 时，立即停止工作，保存当前状态与下一步，等待用户刷新后继续；不使用重置卡。
