# Harness 日志位置与增量恢复点

用户授权接入真实会话位置；无变化复用上次位置；不恢复半截推理，不回滚外部副作用。

- 核心继续独立：统一恢复点引用不可变执行器游标，游标按内容寻址去重。相同核心版本和游标不新增点；核心变更或会话变更产生新点。
- 核心提交通知与原生 session/event 驱动适配层合并捕获，日志落盘、绑定/提交版本验证后发布。工具未完成或日志正在变化时不把中间事务冒充一致恢复点。
- Harness 游标包含会话ID、不可变头指纹、事件数、前缀校验、原生日志定位信息；未改变时不重新刷盘/计算整份历史。
- 使用原生 buildForkSeed 和 SessionPersistence 创建历史前缀分支，原日志保留；恢复点导出的核心写入新目录并绑定对应新会话。
- 测试真实原生 JSONL（Mock模型）、无变化复用、压缩/前缀、后台队列、陈旧版本拒绝、强制退出后核心增量和原生日志读取/分叉。禁止全世界真实模型运行。

## 实施记录

已实现核心游标去重/引用、统一点复用/版本校验、提交通知；适配层原生捕获/刷盘/前缀校验、事件驱动合并发布、指定位置持久分叉和新核心目录绑定。双轴变化独立保存。真实JSONL七会话及真实强杀思考中/SQLite事务中测试通过；48项相关测试通过，NPC回归另列。没有改Agent提示词或工具描述，无付费API。普通错误内部已完成提交不留uncertain，真正中断仍保留。

底层事务可能先于可发布的统一点；未完成工具结果和陈旧捕获都不发布新点。正常打开不自动回滚当前会话；宿主restorePoint准备新分支，返回新根会话供Harness恢复。
