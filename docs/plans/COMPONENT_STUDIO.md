# 客户端组件开发与 Harness 制作 Agent

授权：2026-10-17，用户要求实现客户端内查看/编辑代码、由专门Agent制作标准模块、验证并装配的闭环。基线19f2372。仅在E盘工作；临时数据、测试客户端和构建输出放仓库build；不使用PowerShell启动包装、下载执行脚本或修改安全软件。Windows用户TEMP/TMP保持原设置。禁止重置额度。先保存此计划以便压缩后继续。

## 交付目标

1. 固定v7模块契约：组件身份/版本/依赖、NodeModule入口、配置Schema、显式工具频道、状态与生命周期、验证入口。复用核心NodeModules与ComponentServices，不另造图传播引擎。给出简洁SDK指南和参考组件。
2. 客户端增加组件工作室：目录、代码编辑、原始/修改差异、保存、测试日志、错误反馈、制作Agent会话及应用入口。复用成熟编辑器。手工与Agent修改共用工作副本和验证流程。
3. Harness后端负责原生会话、模型循环、编码工具与权限；不在浏览器/Renderer中执行系统命令。制作任务使用独立组件工作区，显示原生对话及会话身份，不修改核心或隐藏验收测试。
4. 开发后端管理工作副本、路径/版本校验、固定验证命令、进程期限/终止、验证结果、发布到组件库和核心节点装配。测试执行用户模块会产生本地代码执行，不把普通子进程称为安全沙箱。运行中网络不得热换代码。
5. 2026-10-17追加范围：只用NPC小镇作为组件制作、标准化和迁移测试，前两个应用仍不处理。保留原组件作为参考；通过制作Agent完成真实小镇组件迁移，验证显式频道、强度、状态恢复与挂载。测试包含原生Harness Mock模型的真实工具调用；沿用用户已授权的有限付费最小测试，仅在本地配置可用时使用且设硬调用/时间上限，不运行整个世界。
6. 桌面客户端可直接启动开发工作台；正常启动链使用现有可执行程序/Node后端，不再依赖手工挑选失效的JSON，也不使用PowerShell包装。旧三个应用的完整兼容迁移仍独立于本轮，不能声称全部已迁移。

调查原生Harness编码与会话接入接口 → 模块标准与开发服务 → Harness制作Agent桥接 → 前端工作室和启动 → 旧组件迁移验收 → 文档/可见提示词核对/本地提交。

## 追加验收目标：从空框架到完整小镇（2026-10-17）

用户进一步要求：业务组件一个都不由Codex手写，用简单口语化中文交给组件制作Agent，从框架出发完整实现NPC小镇。可使用付费DeepSeek API，过程中可调整核心、制作Agent和工作室。前两个应用仍不处理。

执行边界：Codex只修改通用SDK、宿主、客户端、验收与Agent工作指南；新的小镇业务代码/人格/预设由制作Agent输出。此前时钟与存档试验仅作历史参考，不作为这轮输入源码。原始提示词、每次反馈和验收证据保留在build/studio及文档。新建独立空工作区，不读取旧应用业务源码作为答案。

最新边界：组件Agent只写组件，不生成网络；网络生成Agent以后再做。Codex只写网络/节点参数/提示词等配置来装配，禁止为生成组件手写兼容、翻译或补丁业务代码。出现不兼容时调整通用SDK/核心或制作Agent指南，再让Agent修改组件。原先准备的项目自动生成入口已撤下。

步骤：完善通用组件契约及Harness执行端口 → 普通中文需求生成各个组件 → 验证/真实错误反馈修复 → Codex仅用配置发布装配空网络 → 最小真实NPC与五时刻运行 → 恢复、权限、行动值、互动和出生的边界检查。每个制作回合设最长10分钟，原生模型会话保留，测试实际调用设总请求/时间上限，不自动无限重试。
