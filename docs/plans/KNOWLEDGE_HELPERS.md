# 知识库主 Agent 与单层助手

2026-10-15，用户授权实施。仅修改成品目录，不修改备份，不自动发布。

## 已确定的范围

- 根节点即知识库主 Agent，合并固定检索员、归档员和 Wiki 维护职责。
- 默认自己完成；只有主 Agent 能创建助手，助手不能继续创建。最多两层。
- 创建助手无必填参数；可选 components 收窄业务组件及写入范围，不授予父 Agent 没有的权限。资料读取保留父级允许的范围。
- 使用现有 agent_runtime、agent_messaging/send、AgentNode 私人 Markdown 记忆；不实现第二套循环或 Harness 原生子 Agent。
- 输入任务由框架保存为不可改写的文本节点；主 Agent 和每个助手各有交付文档。独立工作也走同样的交付路径。交付包含来源、版本、位置和实际存储回执。
- 原始任务与助手结果通过节点引用传递，父 Agent 检查后提交自己的交付文档。
- 自然语言入口由主 Agent 处理；读/写入口直接建立相应任务，不增加分类模型调用。
- 通用的任务文档和受限助手组件放 foundation；知识库只配置存储类型与工具、节点连接策略。
- 优先复用上游 Wiki 的操作指南及图分析/检索实现；保留许可证和固定版本。按需加载，禁止另起上游模型循环。

## 实施顺序

1. 通用 task_documents 与 scoped_workers，持久化、单层边界、权限检查。
2. 知识库单主 Agent、组件到工具/数据节点的映射与实际读写权限。
3. 上游 Wiki 薄适配，来源不变、页面维护与健康检查。
4. 最小离线/原生 Harness 验证及 Agent 文档审阅清单。

## 验证重点

无组件参数通用助手；Wiki 专用助手不可写 CSV/SQLite/RAG；资料仍可读；没有助手创建工具且底层也拒绝递归；任务原文不可改；助手只能写自己的交付文档；消息唤醒和恢复；原始文件导入范围限制；两应用共存无权限泄漏。

额度低于五小时剩余 8% 时存档暂停，不使用重置卡。
