# 制作 Agent 与当前协议应用重建

2026-10-18。基线 eccb03e。用户允许付费模型测试、修改制作 Agent 资料和项目实现；优先不动核心，必要时先提交检查点再补通用能力。项目测试、缓存和日志使用 E 盘。C 盘初始可用 16.49 GB，E 盘 867.47 GB；迁移保留原始数据且可恢复，不为腾空间删除用户数据。

## 范围

1. 模块／工具统一制作 Agent：当前 v3 ctx、访问、信号、节点锁、依赖、静态工具与可选前端；工具栏目录增加制作入口，发布到入口虚拟目录。
2. 网络预设制作 Agent：按现有资源与配置制作 v8 网络，目录入口与保存路径一致；开关控制是否允许委托模块／工具制作 Agent。关掉时宿主拒绝委托，打开时只有已验证发布的组件可被预设引用。
3. 采用操作流程、正确与错误示例、小教程和按需读取。先检索复用、再参数化与组合、有缺口才新增。教学例与盲测分开；不把参考过答案的结果标为独立从零制作。
4. 完整 NPC 小镇按旧功能清单在当前协议重建：9 地点、7 居民、五时刻时钟、行动点、位置与工具刷新、库存与交易生产、交流赠送、概率事件、家庭同意与出生、独立人格／记忆、增量存档和恢复。成品由组件、网络配置与通用宿主能力组成。
5. 第一应用只验收固定讨论组＋去中心化协作组，不实现自主操纵网络的根节点。第二应用以知识归档、分类检索与恢复作为跨应用验证。旧协议不加兼容层。

## 工作与证据

- 每阶段本地提交，保留可回滚点；修改核心前单独记录缺口。
- 相同规范前缀换需求时优先分叉历史；改变规范后创建新前缀。记录新增用量，扣除继承基线。
- 先无模型测试，再限定次数的真实制造与应用测试。每个问题最多 20 次修复，避免无限重试；达到上限保留失败证据。
- 不启动或修改用户日常 Harness 客户端，不在源码、提交或报告中记录凭据。模型沿已安装 Harness SDK 的账户能力调用。
- 制作宿主阶段：统一原生 SDK 制作器、工具/网络目录入口、预设委托开关及工作副本文件能力已实现。只提供当前副本、按需教程和组件接口，不提供终端。教程与依赖只读；不声称 Python/OS 沙箱。
- 验证：34 个 Python 定向测试、37 个前端/宿主测试通过；工具与网络目录入口的真实 Electron E2E 通过（build/maker-entry-1792336644675）。
- 真实首次制作：build/maker-paid-1792337133756，records.counter 从空白生成，8 个真实框架测试通过；41 次请求、55 次工具调用。质量审查发现其为测试错误封套放宽参数 Schema，已经补充框架预检异常的正反教程；这一结果只作为首轮能力证据，不能视为成熟模板。制作器现在限制最多20次验证，避免反复无目的修复。
- 新版 SDK 的 JSONL 持久化插件导出已在适配层修正。账户复用范围由用户明确确认，仅限 E 盘既有授权和本次相关内容，凭据不进入模型上下文。
- 官方运行端口作为显式可选扩展提供自身 Agent 执行/存档，默认开发配置不启用；没有加入任意片段创建网络的通道。核心未改动。
- 当前阶段：真实制作通用记录仓，下一步组装可配置业务服务与小镇。
- 用户补充“基于当前网络许愿”的流程：两类制作器均可按开关使用独立网络副本；副本复制配置/状态/文本，禁用原生模型、外部工具与工具箱，文件路径重定位到 E 盘，保留原副本供审阅。源码变化要求重置，不自动应用正式网络。新增4项宿主集成测试通过（包括副本状态与正式网络不互相修改）。
- 通用记录仓和可配置业务服务首次生成完成（8+11项生成测试），独立审查发现记录仓未声明Agent类型，服务测试改用普通节点并放松身份核验；暂不认定业务验收通过，必须修正并由宿主独立测试。
- 制作中暴露核心参数传递缺陷：`key` 撞到 NodeModules._run 的内部形参，`_name/_spec` 也可能覆盖绑定内部值。下一检查点后做最小通用修复和参数保真回归，不增加网络权限。
