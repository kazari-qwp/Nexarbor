# 核心节点锁实施计划

2026-10-18，基线 81cc769。按用户确认实现核心节点锁，不迁移旧应用。

## 行为约定

- 模块可按自身频道和强度申请一组当前可达节点；宿主执行者使用同一核心入口。锁不增加权限、不隐藏节点、不改变连接。
- 等正在执行的其他访问结束后，一起锁定整组节点并保存不可变旧状态，再让申请者开始操作。调用链可重入，其他并发调用、信号与数据读取异步等待。等待后重新验证权限。
- 锁期间存档读取锁前状态；其他节点可独立持久化。成功时整组一次提交并解锁；异常、取消时等待子任务结束、恢复内部旧状态、解锁。
- 节点出边、基本属性、模块状态与已发布元数据、Agent 输入及绑定、节点登记工具和框架拥有的节点资源文件纳入捕获范围。Agent 日志只保存原生日志前缀游标，内部恢复使用 fork，不续接半截思考；宿主外部工具效果不回滚。
- 不在同步网络查询中阻塞事件循环；需要等待节点的查询使用 await。当前 v3 标准收集器和接口说明一起更新。
- 锁按本次调用链持有；不同根调用不能共享所有权。嵌套仅重入已有节点集合，不允许持锁扩大集合；使用超时与取消防止永久等待。

## 实施顺序

1. 节点锁协调器、批量获取、访问租约、异步等待、调用链所有权和自动清理。
2. 核心模块调用、查询、信号、宿主执行接口接入；保留已提交拓扑供外部路由。
3. 锁前快照、存档合并、整批提交及内部恢复；持久化失败停止继续执行。
4. 更新 v3 SDK 说明、收集器与示例，补充确定性并发测试及真实宿主最小验证。

## 验收

验证等待中请求不会阻塞事件循环、活跃访问排空、批量获取、重入及越权拒绝、锁间独立、信号层等待、断链后重验、异常和取消恢复、存档使用旧状态、其他节点独立提交、成功提交后恢复、资源与元数据恢复、锁租约不泄漏。执行已有 v3 定向回归；不使用付费模型。

## 进展

已完成核心协调器、整组锁、重入与等待、调用链继承、超时与取消、死锁拒绝、内部回滚和整组增量提交。模块的网络查询改为 await；访问、信号、工具、执行器和工作台读取接入门禁。

后续确认已纳入实现：

- 持久化以节点记录为拼接单位；出边只记录目标 ID，不递归捕获目标，也不要求锁集合闭合。
- 锁前记录包含 Agent 日志游标。准备游标期间的持久化等待；其他节点持久化时混合锁前记录与未锁节点的新记录。
- 旧记录在业务代码开始前先写入增量日志；即使之后没有其他保存，强制结束进程也可从锁前备份恢复。
- 纯上下文变化写入节点增量；未变化游标不增加提交。失败时原生日志保留，通过前缀 fork 恢复内部上下文并隔离旧执行回调。
- 不迁移旧应用；没有引入 NPC 移动业务或新的改边授权。
