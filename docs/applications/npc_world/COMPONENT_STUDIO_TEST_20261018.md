# Agent 制作组件与纯配置小镇实测

日期：2026-10-18。当前 v7 频道核心；本轮仅处理 NPC 小镇，前两个应用未迁移。

## 结果

12 个标准组件由 DeepSeek Harness 制作 Agent 编写并通过工作室验证。Codex 修改通用核心、SDK、适配器、工作台和验收测试，再用 JSON 组装业务网络；没有手写小镇业务模块，也没有为生成组件补兼容胶水。完整预设为 31 节点、65 条有向连接、9 个场所、7 名初始 NPC，加一个不参与脉冲的观察者 Agent。

| 组件 | 职责 |
|---|---|
| time.text | 五时刻时间文本，信号幂等 |
| action.points | 每拍 10 点，检查、扣除、余额 |
| entity.profile | 资料、金币、物品与统一元数据 |
| resident.context | 人格、常识、地图、首次动机与动态现场输入 |
| agent.activity | 等待宿主 Agent 循环结束，登记完成 |
| place.move | 沿道路迁移在场连接，扣行动值，返回到达事件 |
| social.same_place | 同场交流，离场后的友好拒绝 |
| social.give | 可信发送者的同场资源赠送 |
| chance.events | 独立固定概率与次数上限 |
| local.action_rules | 配置驱动的工作、修理、交易、休息与消费 |
| family.household | 双方同意、婚姻、两天待产与创建儿童 Agent |
| savepoint.counter | 每五拍显式全量存档，重启接着计数 |

源码在 [generated_town](../../../extensions/generated_town)，各组件 `provenance.json` 记录验证产物摘要和逐文件 SHA-256。导出只复制 Agent 的验证产物，另加 JSON 装配描述。初始动机、人格、事件池、业务参数和网络连接都在 [network.json](../../../configs/npc_town/network.json)。

## 真实运行

使用 DeepSeek Harness 原生 AgentLoop、官方账户连接及真实付费模型，7 名 NPC 每拍并行。一天五拍全部闭环完成，共 35 次 NPC 活动；活动执行时间合计 **109.007 秒**。这不包含生成组件的开发耗时及两段运行之间的人工检查时间。第一拍后关闭后端，再从存档续跑剩余四拍，7 个模型会话标识保持一致，没有重新开局。

| 时刻 | 执行秒数 | 结果 |
|---|---:|---|
| 早上 | 29.191 | 完成，信号返回 |
| 中午 | 15.981 | 完成，信号返回 |
| 下午 | 27.904 | 完成，信号返回 |
| 傍晚 | 23.351 | 完成，信号返回 |
| 午夜 | 12.580 | 完成，信号返回 |

本次一天运行的场所规则为 `local.action_rules` 1.0.0。复盘发现批量生产按单扣费的问题，最终组件补充 `cost_per_unit` 配置：生产按单位扣费，交易可按整单扣费。该修正另做公开工具回归，没有重复整天付费运行。

运行中观察到：阿石修好坏镐后回矿坑工作；阿森砍树、卖木材并交流离谱见闻；情侣各自同意登记并完成家庭计划；小路开始与他人交流，之后获得镐子并参与挖矿。工作和移动由实际工具改变状态，主观记忆中的数字仍可能记错，不能用 NPC 的自述代替状态记录。

另做最小真实出生测试：仅启用待产者，第一次脉冲中创建“林念”，该轮不执行孩子；第二次脉冲包含孩子，建立其独立模型会话并正常完成活动。它有自己的记忆文件、人格配置和工具，不复制父母上下文。模型自由选择了姓名，测试没有指定必须叫“林念”。

所有实际模型会话进入同一专用 Harness 客户端的持久化目录。已通过客户端原生 `session/list` 确认一天测试的 7 个 NPC 会话可见；出生测试还产生母亲与孩子两个会话。

## 制作方式与审计边界

先提供详细中文要求、明确依赖接口，再把集成错误反馈给原 Agent。首格时间、真实在场核验、移动事件、离场说明和地点名称等修正均由制作 Agent 完成。同前缀任务复用或分叉原历史，前缀改变则新建会话。每个制作回合有 450–600 秒上限，自动验证反馈最多两轮；没有无限重试。

独立的简短要求为：“帮我做个小镇存档组件，每个时刻的脉冲记一次，记到5次就存一次完整档，重启接着数，同一个脉冲别重复记。只做组件。”它首轮通过工作室验证。

**本轮不是隔离旧源码的盲测。** 虽然工作副本从空白创建，制作记录中仍出现对旧时钟、存档样例和 NPC 资料实现的读取请求；口语存档也查了旧存档代码。因此本轮证明的是 Agent 制作、验证修复、组件复用与纯配置装配闭环，不能据此证明“完全不参考现成实现也能只凭一句话生成完整小镇”。记录中未发现 Agent 在组件工作副本外写入或编辑宿主文件。旧参考读取请求保存在证据 JSON，保守按参考过处理。

生成记录还包含少量目录查询的终端调用；后续指南要求只编辑文件、由宿主测试。不能将当前普通文件工具权限和提示词约束称作严格文件系统隔离。

## 验证与修复

- 无模型集成检查覆盖：行动值、相邻地点与本地业务范围、移动后上下文、首次输入去重、库存原子性、赠送、自己家休息、过时工具拒绝、概率上限、双方同意、十拍待产、出生下一拍参与、并行和恢复。
- 通用配置文档加入核心资源追踪，避免人格、地图、常识在导出或恢复时被遗漏；这项改动不认识小镇业务字段。
- 工具声明在 addition-only 模式中保留历史；当前调用仍重新核验可达范围。压缩后回收不再被引用的停用声明，恢复时保留历史路由，但不恢复已经失效的权限。
- 桌面源码编辑、差异、验证、发布、挂载和脉冲闭环通过实际 Electron 测试；完整 31 节点预设能直接打开并查看只读组件源码。网络文档可在客户端编辑并应用，Agent 执行设置也可直接配置。
- 连续高速拖动的逐帧回归中，6 条测试连线始终显示；筛选、局部整理和直角布线回归通过。

原始运行输出在本地 `build/studio/town-from-empty/day-test` 与 `birth-test`；GUI 输出在 `build/studio/generated-ui-*`，这些目录不提交。仓库保留汇总证据、来源摘要、需求反馈和提示词文本，不包含账户凭据。
