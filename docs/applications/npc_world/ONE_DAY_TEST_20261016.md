# NPC 小镇：一个游戏日真实测试

日期：2026-10-16。结果：通过。用户授权付费实测，未干预 NPC 决策，运行到第1天午夜停止，没有继续第二天。

## 实现

- 通用 input.opening：首次任务与初始处境合为一条输入，标记和待投递事件原子保存，复用原生去重投递；装配不启动模型，恢复不重发。短期目标从常驻元数据移出。
- 通用 probability.events：独立固定概率，实例共享次数上限，null 无限；记录种子、抽取结果与次数。应用在既有行动事务内调用，奖励复用既有物品操作，失败整体回滚。读取不抽取、不额外唤醒。
- 小镇仅用节点配置选择事件与文案；地图 context、常识与人格 system 保持原通道，移动结果增加目的地名称及可选见闻。

## 真实运行条件

使用已安装 DeepSeek Harness 的原生 Agent 循环、系统提示/工具动态更新、权限装配、JSONL 持久化与 DeepSeek Account 官方模型通道。没有另起桌面窗口或操作用户客户端。模型为 DeepSeek-V41-Flash，thinking high，500k 上下文、50k 输出上限。没有 Mock 模型或人工给 NPC 安排具体行动。根仅作为测试操作员，由程序调用五次 world_round，不消耗根模型请求；这验证居民世界运行，不是根自主组网测试。

每时刻 NPC 最多16次请求/90秒，整轮180秒，单次实测硬上限240次API请求、总时限30分钟。

## 错误与本轮修正

首次尝试在第三时刻停止：月宁完成登记后继续读交谈和记忆，到最初8请求上限而未正常结束。该尝试84请求、99.709秒，不计入上面的成功一天。提高真正生效的预设 agent.signal.max_requests 至16（含儿童模板），不使用未被实现的 worldMaxRequests 配置。另修正民政局事件目标节点ID，等待另一方同意时不触发庆祝。

成功运行仍有21次工具拒绝/错误：6次对方移动后旧交流入口不可达、4次重复主要行动、1次超交谈次数、2次结婚参数先填姓名后改节点ID、1次铁匠不在店、1次无工具采矿、6次不支持/无权限的读取。均返回给模型，由其继续处理，未导致居民掉线；这是权限/行动约束和模型试探的实际记录，不等同于零工具错误。

两次付费尝试合计 **223请求、1,997,597 token**：未命中输入190,453，命中输入1,720,192，输出86,952。
