# 知识库应用：真实 Harness 读写验收（2026-10-15）

## 结果

通过实际 DeepSeek Harness 客户端验证首批归档、只读查询、增量更新、重复导入、历史追溯、客户端重启恢复、单层助手协作，以及修复后的 RAG 建索引和中文语义检索。独立程序完成 **74 项数据与日志检查，全部通过**；9 项 Python 最小测试及 4 项原生 Harness 测试通过。测试结束时所有会话均空闲。

这不是一次从头到尾无故障的运行：先用干净工作区完成五阶段存储与恢复，再在同一知识库上补充助手协作和 RAG 修复验证。模型自主选择集合与存储；验收脚本不向模型提供答案，也未替模型写入业务记录。工程中断与重试均保留原始日志。

## 测试条件和资料

- 客户端：DeepSeek Harness 0.2.0-rc.2，独立配置和用户目录。
- 模型：登录账号的 `deepseek-account / deepseek-flash`，`reasoningEffort=high`，输出上限 50,000。实际日志中的上下文窗口为 **1,000,000**，不是准备元数据里原先填写的 500,000。
- 首批输入：13 篇 SQLite/USGS 官方文档快照、300 条 USGS 地震观测、14 条文献目录、来源清单和虚构 QuakeDesk 项目要求。
- 后续才提供：181 条增量观测、项目 v2 变更、WAL 文档的完全相同副本。原始资料和验收答案分开，Agent 仅可导入工作区材料。
- 本次模型选择了 5 个集合：SQLite 观测表、两个 CSV 目录/清单、RAG 技术资料、Wiki 项目知识页。主 Agent 可自行工作，复杂核查使用一名助手，无递归助手。

## 本轮修复

1. **扩展会话事件恢复**：原来的 persistence.append 包装漏掉了原生 enqueueLive 实时写入；改为在取得实际句柄时同时处理两条路径，仅给本扩展的尾部块/错误纠正事件标 ignorable。真实关闭、重启、继续对话与再次冷读回归通过。未修改旧日志掩盖问题。
2. **Wiki 元数据**：YAML 可把数字、布尔值、日期解析为非字符串，导致上游图检查崩溃；在适配层转换标签，保留上游代码与固定版本不变。
3. **Windows 长路径**：fsspec 将 Windows 扩展路径改成 POSIX 形式，导致 LlamaIndex 找不到实际存在的原文；组件内的本地文件系统适配覆盖读取、索引持久化和恢复。
4. **RPC 线程的科学计算库初始化**：临时堆栈显示首次 SciPy 导入卡在工作线程；在可选 LlamaIndex 组件启动时于主线程加载完整 HuggingFace 嵌入依赖，然后再启动工具工作线程。仅预载 SciPy 不足，完整依赖预载后真实客户端完成索引。没有把知识库逻辑写进核心。
5. **检索真实性**：禁止给非 RAG 集合传 semantic=true 后把关键词结果标为 hybrid，返回明确错误；Wiki 检索仍使用自身搜索工具。
6. **参数说明与反馈**：修正来源 locator 的歧义、aggregate.field 的位置说明；无效知识引用返回具体纠正信息，仍严格核查来源、权限和回执。

## 可见边界

- RAG 命中正确文档，但返回片段未必落在最佳论证段落，精确引用仍应读取全文。
- 模型曾把缺少 aggregate.field 的 max/min 错误泛化为“没有计数聚合”，也曾把引用参数错误泛化为“sources 不可用”。实际计数可用，结构化来源验证有最小测试覆盖；不能把模型这两句自述当作框架能力清单。指南已纠正。
- Wiki 孤页/缺失链接属于实际页面质量检查的发现，不等于图检查器崩溃；未替 Agent 修改知识页来消除提示。
