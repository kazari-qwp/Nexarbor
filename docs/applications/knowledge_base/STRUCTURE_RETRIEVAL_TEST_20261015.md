# 结构感知检索验证（2026-10-15）

目标是“检索找到入口、结构展开关系、原文核实结论”。本次只修改扩展，不改变核心框架。

## 实现

- 新增 storage 通用 document_structure 组件，复用 markdown-it-py 的 CommonMark 解析及原文行号，不重写原始资料。
- kb_fetch 支持全文、目录、章节和行窗口；提供父级导语、同级/子级读取入口与分页参数。读取入口固定记录版本。
- 语义检索保留真实片段位置和分数，核实原文后才提供定位；索引原文哈希防止旧片段被引用成新版。不能确定位置时不编造行号。
- 文档最佳片段不再被低排名片段覆盖，同一文档的多个片段不反复增加文档融合分数。kb_index 增加显式 rebuild 参数。
- 有结构文档和无结构碎片可以分别建 RAG 集合，共用组件和嵌入模型；无结构记录返回 has_structure=false，不生成虚假章节。不硬编码必须建两个集合。

## 真实 Harness 验证

使用用户已登录的独立测试客户端，deepseek-flash / high，输出上限 50,000。语义向量来自本地 bge-small-zh-v1.5，未用伪造检索结果替代实际索引。

资料是两份测试规范和一条现场口头记录，分别归入两个 RAG 集合。最终实际保存 3 条原文，当前文档集合 2 个向量，碎片集合 1 个向量；独立读取当前索引确认，不累计历史索引版本。

模型实际执行了 semantic=true 检索、目录、章节、窗口和全文读取。回答正确区分：同机约束、多读者/单写者、跨主机只读快照的例外，以及来自另一份规范的无关条款。读取子章节时实际获得父级条件；碎片被正确识别为无标题结构，且保留未核验来源的限定。

**45 项独立检查通过**：两个集合隔离、三份原文逐字相同、版本均为 1、两个集合均真实语义召回、命中位置有效、各次正文和父级导语对应原始字符区间、四种读取视图使用、父级限制和例外实际读取、当前索引实际向量数。

测试输入有一次明确缺陷：初次没有列出两份规范文件名，而测试 Agent 未配目录浏览工具，导致大量猜测文件名与失败调用。现场碎片阶段通过，但规范阶段不完整；补上实际文件清单后继续同一会话，规范阶段约 64 秒完成。没有提供问题答案，没有替模型整理交付，不将初次尝试算成无故障成功。模型最终叙述中把第二次增量索引返回的累计 chunks=2 误写成第二份文件独有的 2 chunks；独立计数为两份文档合计 2 个向量，以上以实际索引为准。
