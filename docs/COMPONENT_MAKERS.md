# 从效果需求制作组件和网络

模块和工具是一份组件包：模块声明公开操作，`agent_tools` 把选定操作提供给模型。组件前端编辑配置，框架递归装配依赖并去重。

在左侧模块栏或工具栏进入希望保存的虚拟目录，点「制作新模块／工具」。直接写想实现的效果，例如「让目前商店能借还金币，一个人最多欠8枚，原买卖保留」。不必先抽象函数或模块。制作器可查看当前网络或通过 project 指定的任意 Nexarbor 项目，在独立副本中核对真实节点、配置和可达路径。

制作器先查询已有组件，决定交付哪种结果：

| 情况 | 交付 |
|---|---|
| 已有能力，只缺参数 | `presets.json` 配置方案；发布为独立模块书签 |
| 缺少能力或已有模型不适合业务 | 标准 v3 组件、工具声明、可选前端、中文文档与真实框架测试 |
| 需要组装网络 | 网络预设制作器输出 v8 `network.json` 与文档 |

网络预设栏的每一级目录也有制作入口。可以把当前网络复制为草稿，再描述「在目前网络增加……」。全局网络制作 Agent 可委托模块／工具制作 Agent 补充通用能力；网络内局部管理员继续遵守它本身的可达范围和委托设置。成品默认归入入口虚拟目录，对应真实磁盘预设文件。

测试副本复制网络状态、受管理文本和公开资料，给文件重新分配独立测试目录内的路径，清空原生会话位置与执行绑定。真实模型、外部工具和节点工具箱执行关闭，组件公开操作与其工具发现仍可以测试。修改源码后需要重新复制副本，旧副本保留。测试和发布都不自动改正式网络。

验证结果会显示在工作室。先检查变更、配置和测试，再发布。配置方案保存至书签；组件发布到库并归入入口目录；网络保存为真实预设。可以在客户端继续编辑代码和组件前端。

只含配置的书签拖到已有模块时保留原来的访问授权和运行状态；不会因为采用一份参数方案就把授权重置为模板默认值。新节点仍使用组件的默认装配授权，实际能力依赖目标网络的连接和频道。

教学资料按任务逐步提供：局部 ctx、访问与信号、节点锁、工具与前端、真实测试夹具、网络装配、当前网络副本、复用配置。模型只按需读取相应教程与依赖接口；没有终端，也没有全项目搜索工具。工作副本的教程、依赖和参考资料只读。

同一前缀换需求时可以分叉历史；盲测用回答之前的种子位置，避免把旧答案当新能力。正式制作的显式 resume 会检查教程与接口前缀；持续对话保留已读历史，更新后的资料需重新按需读取。单任务限制步骤、时间、验证次数和子任务数，C盘低于2GB时拒绝新制作请求。日志、缓存和测试副本保存在当前项目的运行目录中。

测试执行仍是可信 Python 代码，独立进程与 ctx 接口不等于操作系统沙箱。不要把未知来源的 Python 组件当成不可信代码隔离方案。

示例应用位于仓库和安装包的 `projects/`，内置学习小镇位于 `resources/examples/npc-town/`。先复制到自己的工作位置，再从「工作台 → 打开项目文件夹」选择目录；各项目有独立运行缓存。活动传播由网络连接和模块配置表达，核心保持广度逐层、同层并行。

制作器与咨询器共用 `inspect-network`（查看网络）Skill。初始只展示短目录，加载入口才出现观察工具；筛选、配置解释和路径排查参考按需读取。图片可按类型、模块、频道和边关系组合筛选，支持排除和沿上次视图继续调整。网络制作可观察候选网络 `source=candidate`、本轮当前网络快照 `source=current`，或已建立的测试副本 `source=environment`。每次固定读取快照，写入候选网络或改变测试环境后刷新；局部管理员的来源仍是既有的可达性裁剪副本。观察操作不会装配、执行或修改正式网络。Skill 教程改变会更新制作会话前缀，避免拿旧教程历史直接续写。

两个制作 Agent 同时承担解答和修改，知识分为四个 Skill：`nexarbor-basics`（理解 Nexarbor，纯文本）、`inspect-network`（查看网络）、`make-network`（制作网络）和 `make-components`（制作模块与工具）。后三个用 `skill.json` 声明所需工具，宿主按声明延迟装入工具。两个 Agent 都能读取基础概念和查看网络，再使用各自的制作 Skill；机制、流程、示范和反例按任务读取，不一次塞进提示词。

用户可以先问设计、参数或整体网络，再直接要求修改。同一对话保留上下文，编辑工具首次使用自动建立 Git 工作分支，后续沿用；工作室与悬浮窗口是同一功能的不同入口。同一项目中，每个 Agent 默认续接上次选中的对话，只有点击“新对话”才新增；两种窗口共享历史、输入草稿、附件和运行状态。切换节点、模块或工作副本只改变本轮关注对象；各对象的工作分支分别保留，再次切回会沿用原分支。不需要咨询／制作权限开关。现有发布和正式运行图保留，候选改动完成后验证并展示。

`project_git` 提供状态、分页差异、历史、提交、配置远程、推送和恢复。操作对象是当前项目的制作工作分支；推送支持项目已有远程与指定目标分支，不强推。恢复前自动提交当前工作，再从指定版本建立恢复分支，原进度和对话保留。项目 Commit 保留 Agent 分支的历史父提交，克隆后也能恢复工作副本。

内置小镇完整学习项目位于 `resources/examples/npc-town/`，已替换为本轮交付的初始状态（59节点、19模块），作为普通项目随安装包提供。入口为 `nexarbor.json`，活动网络与出生模板在 `networks/main.json`；项目模块从该项目资源清单定位，不依赖核心目录有同名模块。两个制作 Skill 都强烈建议阅读基础概念 Skill 的小镇案例分析及案例本身；用 view_network(project="项目绝对路径") 开始，之后可沿用项目查询图片、节点、模块源码及文本。此能力也适用于任意其他 Nexarbor 项目；显式 source 切回当前工作流，refresh 刷新外部变更。
