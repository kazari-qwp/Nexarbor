# 从效果需求制作组件和网络

模块和工具是一份组件包：模块声明公开操作，`agent_tools` 把选定操作提供给模型。组件前端编辑配置，框架递归装配依赖并去重。

在左侧模块栏或工具栏进入希望保存的虚拟目录，点「制作新模块／工具」。直接写想实现的效果，例如「让目前商店能借还金币，一个人最多欠8枚，原买卖保留」。不必先抽象函数或模块。开启「允许查看并测试当前网络副本」后，制作器会查看副本中的真实节点、配置和可达路径。

制作器先查询已有组件，决定交付哪种结果：

| 情况 | 交付 |
|---|---|
| 已有能力，只缺参数 | `presets.json` 配置方案；发布为独立模块书签 |
| 缺少通用能力 | 标准 v3 组件、工具声明、可选前端、中文文档与真实框架测试 |
| 需要组装网络 | 网络预设制作器输出 v8 `network.json` 与文档 |

网络预设栏的每一级目录也有制作入口。可以把当前网络复制为草稿，再描述「在目前网络增加……」。开关决定能否委托组件制作器；关闭时宿主拒绝委托，不能仅靠提示词绕开。成品默认归入入口虚拟目录，对应真实磁盘预设文件。

测试副本复制网络状态、受管理文本和公开资料，给文件重新分配 E 盘路径，清空原生会话位置与执行绑定。真实模型、外部工具和节点工具箱执行关闭，组件公开操作与其工具发现仍可以测试。修改源码后需要重新复制副本，旧副本保留。测试和发布都不自动改正式网络。

验证结果会显示在工作室。先检查变更、配置和测试，再发布。配置方案保存至书签；组件发布到库并归入入口目录；网络保存为真实预设。可以在客户端继续编辑代码和组件前端。

只含配置的书签拖到已有模块时保留原来的访问授权和运行状态；不会因为采用一份参数方案就把授权重置为模板默认值。新节点仍使用组件的默认装配授权，实际能力依赖目标网络的连接和频道。

教学资料按任务逐步提供：局部 ctx、访问与信号、节点锁、工具与前端、真实测试夹具、网络装配、当前网络副本、复用配置。模型只按需读取相应教程与依赖接口；没有终端，也没有全项目搜索工具。工作副本的教程、依赖和参考资料只读。

同一前缀换需求时可以分叉历史；盲测用回答之前的种子位置，避免把旧答案当新能力。规范或接口改变则新开会话。单任务限制步骤、时间、验证次数和子任务数，C盘低于2GB时拒绝新制作请求。日志、缓存、测试副本保存在 E 盘。

测试执行仍是可信 Python 代码，独立进程与 ctx 接口不等于操作系统沙箱。不要把未知来源的 Python 组件当成不可信代码隔离方案。

已验收应用可从「工作台 → 示例应用」打开。应用使用独立运行目录，已有工作区的发布版和旧存档不覆盖。应用的活动传播由网络连接和模块配置表达；核心的默认异步访问与同层信号屏障保持原语义。

制作器可用与咨询器相同的网络观察工具：先 `view_network` 看图，再 `inspect_nodes` 批量查模块表、`inspect_modules` 查接口，必要时 `read_resource` 查已用组件文档。网络制作默认观察 `source=candidate`；只有用户启用了当前网络测试授权，才能读 `source=current` 或 `source=environment`。每次固定读取快照，写入候选网络或改变测试环境后刷新；局部管理员的来源仍是既有的可达性裁剪副本。观察操作不会装配、执行或修改正式网络。
