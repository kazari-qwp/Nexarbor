# 网络工作台：Agent 可见文本核对

本次没有修改已有 NPC 的通用提示词、人格、职业知识、世界常识、动机或业务工具描述。新增组件及模板会产生以下 Agent 可见内容。

## 新组件描述

文件：`extensions/editor/capabilities/network_editor/component.json`

> 本地可视化编辑、检查和运行网络。

组件没有新增 Agent 调用工具；编辑、运行、恢复与聊天接口属于可信宿主，不通过模型工具授予。

后续补充的Harness会话栏按钮与测试插件安装修复只面向使用者，没有增加或修改Agent提示词、工具描述或指南。

## 自建小镇地图

生成器：`extensions/editor/capabilities/network_editor/python/datanet/editor/documents.py` 中 `refresh_map`。标题和表头固定，其余内容由使用者建立的场所及道路生成。本次最小测试的完整内容：

```markdown
# 小镇地图

| 地点 | 可直接前往 |
|---|---|
| 小树林 | 商店 |
| 商店 | 小树林 |
```

该文本继续通过已有上下文来源进入持续上下文通道。没有加入行动建议、强制交谈或测试目标。

## 使用者填写的文本

居民人格按填写的原文写入独立人格文档，通过原有系统提示词通道装配；初始动机按填写的原文配置到 `input.opening`，仅首次输入。前端不额外添加世界观或操作要求。

已有模板中的 Agent 会话提示词、活动指南、身份知识以及脉冲任务继续引用原组件资源或原配置。模块编辑器表头、按钮、配置 Schema 标题属于人类界面文案，不会被自动注入 Agent。

## 仅测试使用的输入

浏览器验收向人格表单填入以下内容，标记仅用于 Mock 回复识别，不是产品默认人格：

```text
[Editor A] 你是一个友善的伐木工。
[Editor B] 你是一个友善的伐木工。
```

两位居民的测试动机均为：

```text
和邻居聊一聊，砍木材后去商店。
```

根会话的测试首条输入为“网络工作台最小测试就绪。”；聊天入口测试发送“测试对话入口，请回复一句。”。这些内容只保存在测试脚本及测试日志中，不会进入实际新建居民的默认输入。
