# 局部网络管理员

在左侧节点栏把“网络管理员”拖进画布，再从管理员向准备交给它工作的节点连边。默认只组装已有组件。
管理员是普通节点加官方 `network.administrator` 模块，携带五个 Agent 工具，也可装到已有 Agent 节点。

## 范围与模式

工作范围由管理员模块的 `access.strength` 和 `access.channels` 沿实际有向连接计算，直接使用核心的频道、阈值、倍率与发散机制；管理父子关系和客户端筛选不授予权限。
模块调用本身走 `admin` 频道。模块的默认强度是 2，可在右侧“网络访问授权”中调整。
官方端口需显式声明 `extension: {operations: ["manage"], targets: ["$self"]}`，这里只表示调用管理员自身的受限服务，不能获得全网访问。

- **仅组装已有组件**：不提供 `request_component` 工具，模型无法靠提示词打开此能力。
- **允许委托制作模块／工具**：在模块配置中勾选开关并应用网络。子制作器的“当前网络”测试副本也继承管理员的局部范围。

## 使用流程

1. 应用网络。选中管理员，打开右侧“模块”，展开“局部网络管理员”。
2. 点击“查看可达副本”确认范围。副本的 `root` 是管理员锚点，不是全网根节点。其他可见节点使用局部别名；外部引用使用不可解析的占位标记，边界外节点、出边和原生日志不提供给模型。
3. 描述需求，点击“委托制作局部网络”。记录任务号，通过“查询进度”查看简短结果；运行中默认等待15秒，最多可设置30秒。只有诊断时才用 include_log 分页展开日志。
4. 完成后点击“提交已完成草稿”。新节点分配全新编号，内部连接、显式准备入口、工具来源和 Schema 声明的节点引用一起重映射。成功后画布自动刷新。
5. 根 Agent 也能沿 `admin` 频道访问管理员的五个工具，完成同样流程。`build` 的 `key` 用于防止重试重复启动收费任务；`apply` 有随存档持久化的提交回执。

## 提交与并发

模型只改独立副本，制作期间正式网络继续运行，不持节点独占锁等待模型。
提交先重新检查当前可达性、管理员模式和配置版本，等待相关节点已有调用结束，然后在短协调区内同步完成增删节点、普通模块装配和可见连接修改。
核心新增的宿主 `NodeLocks.mutate` 只负责排空调用与同步提交，不向普通 `ModuleContext` 暴露。具体资源的失败回滚由管理员服务负责。

已有组件的最新运行状态、Agent 会话和上下文位置保留。未编辑的节点文本保留最新内容。拓扑、配置或真正准备修改的文本发生并发冲突时，拒绝覆盖，需重新制作。
已有节点可以改名称、说明、可见出边和普通模块配置，不能借此覆盖状态、扩大旧授权或改变执行身份。管理员自身锚点不允许重新装配模块。
新增组件、Agent 执行绑定和脉冲的强度、频道都不能超过管理员授权。普通组件依赖仍按标准规则递归装配。

不允许指向副本外的新出边，不允许装配其他官方越权模块或授予外部系统工具。原有边界出边和外部引用原样保留；仍被外部连接、管理父级或委托许可引用的节点不能删除。
删除节点不销毁原生会话日志，失败会恢复节点、组件、连接和此次修改的文件。提交回执与网络一起存档；重启后重复提交不会再次创建节点。

## 示例与验证

可打开 `configs/network_administrator/profile.json`，或自行拖入管理员。示例中管理员只看得到自身、“工作区”和“二级资料”；“范围之外”和“私有节点”不在它的范围内。
示例根节点未自动运行模型。可手动操作管理员，也可自行给根节点配置执行器并沿连接发现管理员工具。

本地维护验证覆盖真实后端权限、并发提交、状态保留、失败回滚、冷恢复、宿主调用及客户端交互。相关测试脚本和运行记录不随发行内容发布；普通项目可通过制作器的独立测试副本按需核对管理员的实际行为。

隔离沿用可信 Python 的能力边界与独立测试副本，不能把它解释成操作系统级 Python 沙箱。
