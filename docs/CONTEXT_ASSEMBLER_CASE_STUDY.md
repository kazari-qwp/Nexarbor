# 上下文组装：反例与正例

## 反例：把一个应用藏在“角色上下文”模块里

保留的反例是 agents.context，原始版本可从 Git 提交 d963be0 查看。代码保留用于理解和旧项目读取；新小镇不再装配它。

这个模块的 prepare 同时拼人格与世界规则、按职业匹配知识、读取场景与时钟、发布人物资料、排队开场输入，还附带私人记忆、地点和地图工具。模块名看似通用，实际强依赖 records.store、place.info 和 clock.counter。更糟的是执行器还无条件添加了一句记忆提示，活动模块又偷偷调用 prepare。这些都是本次实现应当避免的设计错误。

```python
# 反例的实际路径：规则、地点、钟表被一个 prepare 隐式捆在一起。
snapshot = await _snapshot(ctx)   # 内部读场景、钟表、人物记录
ctx.update_inputs({"system_prompt": snapshot["system_prompt"],
                   "context": snapshot["context"], "tail": snapshot["tail"]})
```

用户看不到“钟表 → tail”的连线，也不能独立换掉某个来源。改时间显示必须改场景代码；迁移到其他应用时带走一串不需要的地理/身份假设。给一个模块继续加十几个开关不能解决职责边界问题。错误的抽象不能只靠减少输出字段来修补。

同样不该用节点锁包住整个装配。这里都是读取，没有需要隐藏的多节点中间态。锁住角色等待模型或查询会扩大阻塞范围。

## 正例：配置决定行为，连线说明来源

```text
角色 ┄┄归属┄┄ 上下文亚节点（普通 context.assembler 模块）
                ├─context.assembler.system_prompt─→ 人格 / 世界规则
                ├─context.assembler.context───────→ 适用知识
                ├─context.assembler.inputs────────→ 一次性事件
                └─context.assembler.tail──────────→ 时钟普通文本
```

亚节点有独立的模块表、工具表和出边。归属虚线不是业务边；角色通过显式 prepare 本地调用模块，不消耗寻路预算。四类文本分别遍历，不能借业务频道扩散。默认不共享父子出边，有需要时由核心的两个开关分别开放，模块不维护这些表。工具收集器也可放在另一亚节点，显式列入 execution.tool_sources；不把它的工具和模块混进父对象的列表。

串联用独立的 context.assembler 频道访问其他组装器，按去重广度顺序合并各组装器自身的来源，不递归把深层来源提前插入，通过已到达节点对象直接调用；各实例使用自己的装配授权，不再把路径或剩余强度交回核心重新寻路。每类频道都可配置列表与黑白名单，界面用条目和加号。

已有文本可以直接接线；短文本可以直接填进 sources；项目文档可用相对路径。不要因为要换一份规则、角色或时间格式就制造新模块。配置和当前正文一起决定四路结果。

工作台预览与正式运行调用同一只读装配函数，显示来源与错误；预览不能消费 inputs。实际投递由 Agent.execution.prepare 的显式入口完成，一次性事件的去重回执由现有核心接口保存。记忆检索、地图查询和活动调度各自独立，不挤进装配器。

## 制作流程

1. 先问哪些正文是系统指令、长效资料、一次性事件、每次更新的尾部。不能把全部信息塞 tail。
2. 查目录复用 context.assembler，直接连接普通文本；不要求 context.text。需要独立出边时才建上下文亚节点，先完成一个角色和两份文本的闭环。
3. 给角色配置显式本地 prepare。按四种频道从亚节点接资料，分开业务频道。
4. 沿对应频道可达的文本无条件纳入。需要动态变化时，由业务模块修改连接，组装器不按人物字段或 bindings 再过滤。
5. 在工作台预览来源。验证广度顺序、重路去重、环路、错频道隔离、文件越界、连接变化更新资料、事件只投递一次。
6. 再扩数量。更换角色或业务时优先换文本、参数与连线。只有通用接口确实缺失才增加组件。

## 迁移保护

小镇 migration 先备份运行状态和工作页。原私人记忆移至 agents.memory，已投递/待投递开场回执保持状态；移除旧模块的当前输入快照，不抹去历史对话。地点、个人记录、消息、活动状态与上下文游标保留。新生模板为各实例配置独立正文、组装器和工具来源，复制时重定向准备入口与资料连接，不能回指原角色。当前初始样板的组装器在居民本节点，工具收集器在亚节点；模板位于 `resources/examples/npc-town/networks/main.json` 的 `runtime.templates`。

完整正面样板随安装包位于 `resources/examples/npc-town/`。两个 Agent 强烈建议先读基础概念 Skill 的 `references/lessons/13-town-evolution.md`，再用 inspect-network 的 project 参数按需研究完整案例。
