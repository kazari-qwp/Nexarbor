# 小组讨论网络使用指南

## 这个小组怎么工作

预设创建固定的 Leader、Recorder 和可配置数量的普通成员：领导者负责讨论方向和分歧决策，记录者维护公共笔记并整理最终成果，普通成员贡献分析与建议。`member_count` 只计算普通成员，默认3，范围1—64。每人有独立会话和个人记忆，讨论中保留自己的上下文。

小组共享项目说明、讨论黑板、公共笔记和成果文档。项目说明由组装者准备，公共笔记和成果由记录者维护。每轮成员读取相同的上一轮发言快照，再提交本轮意见或选择跳过。程序负责轮次调度、历史归档和快照切换；讨论结束后安排记录者汇总并返回成果。

预设已装配成员提示词、讨论工具和必要的内部接口。成员使用的 read_round、submit_round、skip_round 由框架提供，组装者无需再次添加，也无需逐个启动成员。成员自身通过 datanet_discuss 调度；普通 datanet_call_agent 用于委托其他普通 Agent。

默认八轮，每名成员每轮最多十次模型请求。创建时可选择轮数，程序向成员提示轮数与请求次数。

## 使用时你应该做什么

1. **准备项目说明。** 填写目标、背景、约束、当前工作、已有结论和验收标准。创建时可用 project_nodes 引用一个或多个已有查询文本节点，框架将同一批资料接到黑板和所有成员；不提供 project_nodes 时必须用 project 填写非空说明，框架自动创建查询文本。两种方式只选一种。讨论开始时黑板的 load_project 工具将全部资料按节点首次加载到成员上下文，成员后续可通过绑定查询工具按需读取。公共笔记的最新正文自动放在每次请求尾部，Recorder 用 write_resident_text 维护；成果仍写入 output 节点。
2. **创建完整小组。** 使用 datanet_create_network 选择 discussion_group，确定挂载位置和讨论轮数。使用返回的 group_id、成员 ID 和文档入口，不猜测路径。
3. **启动讨论。** 使用 datanet_discuss 下达本次问题、交付要求及必要的执行授权。背景放项目说明，讨论目标通过调度工具传入。黑板发言由成员提交和程序管理。
4. **验收成果。** 调度成功后取得记录者整理的结果，检查结论、执行证据与交付物，再向上级或用户汇报。需要持久成果时读取返回的 output 节点。创建成功即可开展业务，无需额外测试框架装配。
5. **处理失败与未完成任务。** 区分业务执行失败和讨论调度未完成。成员报告失败但讨论与归档完成时，按委托要求正常返回失败结果，不自动修复或上报自身阻塞。调度未完成时保留已建小组，按返回信息或 handle_problem 流程处理，并以原小组和原任务继续。排障未解决但仍可交付时用 problem_defer 保留影响后退出；自身委托确实受阻才 datanet_feedback。已完成小组返回已有成果；新议题可另建小组。

### 按需扩展组织

可以在小组上方安排协调员，在成员下方增加操作员或专题小组。新增角色应服务于明确的职责、执行能力或上下文需求。

用 datanet_create_agent 一次创建带个人记忆的下属 Agent 节点。给成员增加下属时，开始讨论前用 datanet_manage_agent 查看并持久更新其提示词：保留原讨论角色，补充下属实际 ID、委托职责、结果回收和向小组汇报要求。同时按新增职责装配工具箱并建立访问接口。成员默认已有 datanet_call_agent；文件、终端或管理等能力按职责另行授予。

具体参数和调用格式以各工具的描述与 schema 为准。
