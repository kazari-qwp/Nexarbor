# 委托报告存储与按需读取

实现文件：`reports.js`、`report-channel.js`；集成入口：`index.js`、`incidents.js`。Agent 首次进入通道时读取 `guides/tools/datanet_reports/AGENTS.md`。

## 存储与分工

报告根目录固定为插件 `storage` 下的 `reports`，无需创建节点时填写参数。最初请求、各级委托和各次运行采用 UUIDv7，节点 ID 存在元数据和节点索引中。目录按照实际委托关系嵌套；同级发起顺序由串行存储写入器分配。委托树与网络静态连接分开，支持从任意已挂载 Agent 发起请求、同一节点多次参与、跨网络调用以及讨论调度。

直接委托返回仅携带被委托者的结果和 `report_reference`，不会自动将整棵树的正文或引用累积到最顶层。报告保留完整文本；索引用于按需定位。讨论容器、每轮成员调度、成员再次委托和最终 Recorder 归档均进入同一请求的实际委托树。

`manifest.json` 保存委托、运行和归档授权。`topology.json` 保存父委托、调用者运行与发起序号。`node-index.json` 以原始节点 ID 映射到各次委托的运行文件。索引路径相对于该根请求目录，读取不需要逐层翻目录。元数据与索引由框架生成，Agent 不负责拼目录或写索引。

运行文件包括完整报告、工具参数和结果、运行消息、本轮提交、错误原文，以及 Recorder 实际写入的成果快照。只有存在的可读产物登记在 `files` 中。报告、运行汇报及错误记录保存脱敏后的全文。

## 加载机制

首次真正发起委托或讨论调度后注入入口描述，普通创建节点或 Agent 不触发。首次进入入口后才注入指南、索引工具与报告专用读取工具。正文仍在上下文时不重复注入；被压缩后，再次进入才重新加载。已开放的查询和读取工具继续保留。新上下文根据持久化的实际委托或归档授权恢复入口；指南在再次进入时加载。Recorder 在讨论调度时获得该讨论分支的明确归档授权，不据“是否有直接子 Agent”判断。

完整描述原文由 `report-channel.js` 的 `REPORT_DESCRIPTIONS` 定义，文档不再复制一套描述，避免漂移。报告入口属于普通查询，不包含问题通道的状态机、修复要求或重试要求。

## 报告工具权限

报告工具按实际委托关系读取：节点自己的运行、该节点发起的委托子树，以及显式授予 Recorder 的讨论分支。不会因为拿到 UUID 或文件路径就授权。索引与拓扑经相同权限过滤，专用读取工具只接受已登记运行文件或过滤后的索引，不接受任意文件路径；拒绝路径穿越和指向请求目录外的链接。原有节点管理、接口访问和 Agent 委托权限保持原实现，本通道不扩大它们。

这些是报告工具的权限边界，不是给同一操作系统账号建立额外的文件隔离。已有官方文件与终端工具仍受其原有宿主权限约束。本改动没有把原有工程工具改成网络权限工具。

## 生命周期与限制

工具结果在执行过程中逐条写入 JSONL；结束时保存完整报告、消息及状态。元数据和索引用临时文件加重命名替换，写入串行化。宿主启动时把残留的 running 记录标为 interrupted，已有工具证据保留，不自动重放。重试生成新委托和运行，前次失败运行通过 `retry_of` 关联；不覆盖前次报告。

历史目录与索引不做自动迁移或自动删除。每次启动从现有请求清单恢复。读取分页避免一次把全部历史塞入模型上下文；存储原文没有长度截断。实际工具返回的输出可能受该工具自身限制，框架保存收到的原始结果，不声称补回工具已丢弃的内容。

本次修改只增加报告存储、读取和调度证据连接，未修改模型的核查策略、排障预算或工程工具权限。
