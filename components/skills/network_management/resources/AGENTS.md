# 节点网络组装指南

## 网络的基本性质

节点承载数据、业务工具或 Agent；无数据节点也可以作为组织入口。Agent只能依附在某个节点上，可以创建无数据节点搭载agent。读写接口控制数据和节点业务工具的访问，管理归属控制创建、调整及管理下属的范围，两者分别授权。

每个 Agent 有自己的提示词、上下文、工具箱和 Skill。其他 Agent 不能直接使用它的私有工具或 Skill；需要它执行工作时通过任务委托协作。节点业务工具可以按需暴露给上层，经获准接口发现和调用。

创建结果中的实际 ID 用于后续操作。结构可见不代表拥有数据访问、工具使用或管理权限。需要保存资料或成果时使用数据节点，并指定写入负责人。

## 搭建流程

1. 判断是否需要分工。简单任务直接完成；独立职责、上下文或协作需求可拆成节点或子网络。
2. 查询节点、Agent 和网络预设，选择合适组件。也可以自行搭建拓扑。
3. 创建节点和连接，按需准备数据文档；需要智能成员时挂载 Agent，明确职责、输入、交付与验收标准。
4. 按职责装配宿主允许的工具箱和 Skill。提示词不能代替工具装配；默认能力与注意事项见随本指南加载的常用经验。
5. 按信息流设置读写接口，可选将节点业务工具暴露给上层。管理、数据访问与任务委托分别满足对应授权。
6. 委托任务或调用子网络的业务入口，回收并验收成果。框架负责装配校验，无需在用户任务中重复测试建网机制。
7. 扩展已有成员职责时，同步更新其提示词、工具装配和接口。发生影响任务继续的问题时进入 handle_problem，按加载的流程处理。

具体操作、参数与限制以对应工具描述和 schema 为准；预设的工作机制与使用流程见各自 AGENTS.md。

## 组织设计参考

预设是积木，可以组合和扩展。你可以直接对接多个小组，或让子经理、协调员负责拆分与交接；也可以在成员下方增加专题小组，在需要实际操作的地方安排操作员就近执行和验证。给成员增加下属时保留原职责，并补充委托、结果回收和汇报要求。

按任务自主选择组织层级和连接方式；增加角色应服务于明确需求。如果你在任意网络/节点预设下挂载了新的节点，记得给该节点配上相应的工具以及修改他的提示词（如果有agent的话）
