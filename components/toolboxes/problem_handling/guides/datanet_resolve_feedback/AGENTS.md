# 管理者处理报错

先判断下属失败对自己当前委托的影响。收到反馈不自动要求修复，也不代表自身阻塞。当前委托允许记录和交付失败时，保留失败、证据和已有成果并正常汇报；若已进入排障，使用 problem_defer 记录原因、影响和继续依据。只有未解决问题确实使自己当前委托无法继续或交付时，才通过 datanet_feedback 上报自身阻塞，并填写 task_blocker。需要修复时按现有权限执行下述步骤。
收到下属反馈后，用反馈中的 node_id 作为 target。框架核验实际管理者和真实报错记录，允许沿这个修复通道跳过普通网络路径。省略 target 为本地；其他节点不能用随意填写的地址直达。
inspect 查看报错及现有职责、工具箱。instruct 补充本次指令，普通 Agent 会继续执行并返回结果；讨论成员保存补充职责，随后通过 datanet_discuss 恢复。
update_prompt 替换完整长期职责，保留上下文。add_toolboxes 补充宿主允许的工具箱，不移除已有工具。运行中不支持改变官方 Skill 授权集合；新增官方工具是否可用以返回结果为准。
目标需已挂载且空闲。修改配置不等于任务已成功，继续任务后按实际输出验收。报错历史仍保存，不通过本工具自动将事件标为解决。有些时候是下属没搞明白状况，不一定是真的有什么问题，这种情况沿着通道送个补充说明就行。

## 修复后如何继续工作

inspect 只查看状态。update_prompt 和 add_toolboxes 只修改配置、保留上下文，不会自动启动目标 Agent。

普通 Agent：完成需要的配置修复后，再用本工具的 instruct 补充说明，例如“已补齐工具，请继续原任务并返回结果”。该操作立即启动原会话，等待并返回执行结果；无需重新创建或清空上下文。仍使用真实报错反馈中的节点 ID，通过管理者修复通道操作。

讨论成员：配置修复或 instruct 补充职责后，由小组调用方再次调用 datanet_discuss，沿用原 group_id 和原 task。讨论程序跳过当前轮已经提交的成员，继续未完成成员，再完成剩余轮次及记录者收尾。修复工具本身不单独启动讨论成员。

配置更新成功只表示修复动作完成，继续运行后的实际结果才用于判断任务是否恢复。再次报错时按新的反馈处理。

本说明、通道描述及工具仅在管理者首次收到真实 datanet_feedback 时由框架注入。普通失败结果和 problem_defer 不触发开放。开放后的入口和工具持续保留；说明正文被压缩后，再次进入通道时重新加载。恢复会话时依据已有真实反馈历史恢复开放。目标操作仍需通过管理者和真实报错记录校验。
