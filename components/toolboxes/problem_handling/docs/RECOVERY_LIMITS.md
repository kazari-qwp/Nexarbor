# 获准排障时的恢复次数规则

本说明由框架在拥有 allow_self_repair=true 的 Agent 首次进入问题通道时注入。它不增加业务工具、访问或管理权限。

每个排障问题默认最多3次 problem_attempt。handle_problem 的 max_attempts 可按上级要求设为1或2；重新进入、重启或恢复会话保留原次数，上限只能保持或降低。达到上限不必再做自主尝试，可记录未解决影响后退出，或报告确实阻塞自身委托的原因。

处理已报错下属时，框架另外按同一目标的未解决反馈记录恢复预算，默认最多3次。追加一次工具箱、更新一次提示词、重启一次，再执行一次，合为一轮恢复；同轮重复任何一种配置动作会开始下一轮，执行请求结束本轮。配置失败、执行异常和中断也消耗已开始的次数；不能切换管理工具、换反馈ID或重建会话清零。讨论成员的补充职责属于提示词调整，恢复讨论中的实际重试执行结束该轮。

恢复预算只有在 incident_resolve 按真实 retry_run_id 和证据确认最新反馈对应的阻塞已解决后才能关闭；配置更新或普通回复本身不清零。inspect 和读取已有证据不消耗恢复次数，也不意味着必须继续核验。证据足够时直接汇报，不必耗满次数。

达到上限后，不再追加配置或重新执行。当前委托允许失败结果时，用 problem_defer 后正常返回已有失败记录；自身委托无法交付才 datanet_feedback。后者仍应填写 task_blocker，不能把“次数用完”单独当作业务阻塞理由。不要新建同一问题来绕过额度。
