# Agent 通信

普通 Agent 默认装配 `datanet_send_message(target, content)`；讨论小组成员不装配。主动联系人仅为当前管理者和直接被管理 Agent，框架自动展示其节点 ID。

创建时将创建者登记为 `manager_id`，管理者保存 `managed_ids`。后端绑定接口修改 manager_id 时，在同一检查点更新目标和两位管理者的列表。`creator_node_id` 保留为创建历史。节点挂载树继续描述黑板等数据节点；Agent 通信不沿节点树推导。

每次收到主动消息或回复，框架装配独立的 `datanet_reply_<消息ID>`，仅填 `content`。描述原文：**仅用来回复此条消息，调用一次后失效**。回复固定送回原发送者；成功接受后撤下该工具，并为接收方开放新的单次回复工具。多条未回复消息各有自己的工具。

消息使用 Harness `steer`：运行中在步骤边界接收，空闲时启动一轮。来源记为 `agent-message`，保存发送者会话身份。返回值是投递回执，不是对方的答复。框架不会自动代写回复。

回复权限默认保留 30 分钟，统一由宿主 `messageReplyTimeoutMs` 配置；到期撤下工具。消息和已使用权限持久化，恢复会话不会重新授予已经使用的入口。目标未挂载时返回投递失败。

讨论成员处理独立消息时不触发本轮提交提醒，也不消耗讨论请求次数。正式讨论仍由原调度器控制。任务委托继续使用 `datanet_call_agent`；本次改动不改变其执行方式。真实阻塞仍走 `datanet_feedback`，接收者和修复权限改为当前管理者。
