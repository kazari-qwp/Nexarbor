## 1. 为什么单机 QuakeDesk 适合 SQLite

[[1a029f7c890045ef8be0e67ab6d92078]]（Appropriate Uses For SQLite，source 0001）

- SQLite 提供的是「单个应用的本地数据存储」，与客户端/服务器数据库解决的是不同问题；它强调经济、效率、可靠、独立、简单。
- 适合：嵌入式设备/IoT、应用文件格式、低到中等流量网站、数据分析（可从 CSV 导入后切片汇总）、企业数据缓存、数据交换容器、临时库、演示与教学。
- 不适合：多机通过网络同时直接访问同一库（网络文件系统锁不可靠，可能损坏）、高写入并发、超过单文件容量的超大数据集。SQLite 理论上限 281TB，但实际建议远早于此就考虑集中式方案。
- 关键限制：**同一时刻只允许一个写者**，读可以无限并发；写事务通常只有几十毫秒，多写者靠排队。

## 4. 查询与写入能力

- [[6f64bfbb2c9543008c6e4195ae60b431]]（The WITH Clause，source 0006）：公共表表达式、`WITH RECURSIVE`、`MATERIALIZED` / `NOT MATERIALIZED` 提示；适合层级数据与递归展开（例如按区域层级汇总观测）。
- [[de912303b6524cefa452f861e4382996]]（UPSERT，source 0007）：语法自 3.24.0（2018-06-04）引入，3.35.0（2021-03-12）起支持多 ON CONFLICT 与无冲突目标的 DO UPDATE；仅对唯一性约束生效；`excluded.` 前缀取「本该插入的值」；`DO UPDATE` 冲突算法固定为 ABORT；虚拟表不支持 UPSERT。
- [[160027260de741c1a7101afc370f3478]]（JSON Functions And Operators，source 0005）：默认 30 个函数、2 个运算符、4 个表值函数；含 JSON 有效性、构造、查询、修改、JSON5 输入等。**3.44.0 无 JSONB、无 `json_pretty()`。**

## 5. 版本边界（务必分版本引用）

| 版本 | 新增 | 对本项目的影响 |
| --- | --- | --- |
| 3.44.0（2023-11-01，[[f7751b727bf54732be006625a972c621]]） | 聚合 ORDER BY、`concat()`/`concat_ws()`/`string_agg()`、`strftime` 新转换符、建表错误提前、`integrity_check` 扩展、`case_sensitive_like` 废弃 | **当前可用基线**；不要用 `case_sensitive_like` |
