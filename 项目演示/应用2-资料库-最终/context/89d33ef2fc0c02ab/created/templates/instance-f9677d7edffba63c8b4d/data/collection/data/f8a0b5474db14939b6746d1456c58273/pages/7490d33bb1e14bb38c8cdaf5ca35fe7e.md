## 3. 技术约束（以 3.44.0 为准）

### 3.1 单机本地存储是合适选择

SQLite 面向「单个应用的本地数据存储」，强调经济、可靠、免运维，适用于设备本地、低写入并发、数据量小于 1TB 的场景；同一时刻只允许一个写者，写事务通常只有毫秒级，多写者靠排队即可。官方也明确：如果数据与应用之间隔着网络、或需要大量并发写，应改用客户端/服务器数据库。
来源：[[1a029f7c890045ef8be0e67ab6d92078]]（Appropriate Uses For SQLite）。

QuakeDesk 是单机、单用户、持续追加观测，符合上述适用条件；但若将来多人共享同一库文件（例如放在网络盘），属于原文明确不推荐的用法。

### 3.2 3.44.0 已有的能力

- 聚合函数可在最后一个参数后加 `ORDER BY`（对 `string_agg()`、`json_group_array()` 有意义）。
- 新增 `concat()` / `concat_ws()` 标量函数、`string_agg()` 聚合函数。
- `strftime()` 新增 `%e %F %I %k %l %p %P %R %T %u` 转换符。
- `CREATE TABLE` 相关的许多错误改为在建表时立即报出，不再延迟到首次使用表。
- `PRAGMA integrity_check` 校验 FTS3/FTS4/FTS5/RTREE/GEOPOLY 虚拟表内容。
- **`PRAGMA case_sensitive_like` 在 3.44.0 被废弃**：当 schema 含 LIKE 运算符时使用它，可能导致 `integrity_check` 误报数据库损坏。

来源：[[f7751b727bf54732be006625a972c621]]（Release 3.44.0）。

### 3.3 3.44.0 尚不具备的能力（版本边界）

- **JSONB 与 JSON 函数重写**、`json_valid()` 的第二参数：自 3.45.0 起才有（[[1b286fd88fcc4a4493a14fea2f22904d]]）。因此在 3.44.0 上不要按 JSONB 二进制格式设计存储。
- **`json_pretty()`**、`strftime()` 的 `%G %g %U %V`、数值字面量中的下划线分隔、`PRAGMA optimize` 增强：自 3.46.0 起才有（[[5608548ffb6e42ffbd03b8a6763e3fa0]]）。
- 引用这些特性前，必须先确认运行版本；需求 v1 固定为 3.44.0。

### 3.4 容易踩坑的默认行为

- **外键约束默认不强制**：SQLite 很早就能解析外键，但为兼容历史库，默认关闭强制执行，需用 `PRAGMA foreign_keys` 在运行时打开（或编译期 `-DSQLITE_DEFAULT_FOREIGN_KEYS=1`）。见 [[51e704b5f5494fad997689aaf2b1951c]] §4 与 [[2db67ce011d7497c9b5c68324781aee2]]。
- **没有独立的 BOOLEAN / DATETIME 类型**：TRUE/FALSE 通常就是 1/0；日期时间用 ISO-8601 文本、Unix 秒或儒略日 REAL 存储。本库 `time_utc`/`updated_utc` 采用 ISO-8601 文本，保留原始 UTC 与时区标记 `Z`。见 [[51e704b5f5494fad997689aaf2b1951c]] §3.1、§3.2。
- **灵活类型**：列类型是建议性的，向 INTEGER 列插入 `'wxyz'` 不会报错而是原样存字符串；数据质量需在应用层或查询中校验。见同页 §3。
- **PRIMARY KEY 列可能为 NULL**（历史遗留缺陷），除非该列是 INTEGER PRIMARY KEY，或表使用 WITHOUT ROWID / STRICT。见同页 §5。
- **整数与文本不相等**：`SELECT 1='1';` 返回 false（0）。见同页 §13。
- **双引号字符串字面量被容忍**：拼错的双引号标识符会被当成字符串而不报错，建议统一使用单引号并在编译/连接层关闭该特性。见同页 §8。

### 3.5 写入并发与日志模式

WAL（Write-Ahead Logging）自 3.7.0 起可用，是默认 rollback journal 之外的另一选择；它会引入 `-wal` 与 `-shm` 辅助文件，并涉及 checkpoint（自动与应用程序发起两类）、WAL 文件过大、以及 WAL 模式下查询可能返回 `SQLITE_BUSY` 等事项。
来源：[[5f2179ef15074a4d822a636a45d41c8b]]（Write-Ahead Logging，含 2.1 Checkpointing、2.2 Concurrency、9. SQLITE_BUSY；该页 §11 另记 WAL-Reset 缺陷）。

跨连接、跨事务的可见性与隔离行为见 [[b3ac647545f54db7a74aa4457b189619]]（Isolation In SQLite）；具体结论需按该原文的「数据库连接之间」与「同一连接内」两节分别核对，本页不复述未核对的细节。

### 3.6 追加、去重与查询写法

- **UPSERT**：`INSERT ... ON CONFLICT(...) DO UPDATE/NOTHING`，仅对 UNIQUE/PRIMARY KEY 等唯一性约束生效，对 NOT NULL、CHECK、外键失败不生效；`DO UPDATE` 中引用未修改值用原列名，引用「本该插入的值」用 `excluded.` 前缀；当 INSERT 的取值来自 SELECT 时，需给 SELECT 加 `WHERE true` 以消除 ON 的解析歧义。UPSERT 语法自 3.24.0 引入，多 ON CONFLICT 与无冲突目标的 DO UPDATE 自 3.35.0 起支持——3.44.0 均可用。
  来源：[[de912303b6524cefa452f861e4382996]]（UPSERT）。
- **WITH / 递归查询**：公共表表达式与 `WITH RECURSIVE` 的语法、`MATERIALIZED`/`NOT MATERIALIZED` 提示见 [[6f64bfbb2c9543008c6e4195ae60b431]]（The WITH Clause）。
- **JSON 处理**：默认提供 30 个函数、2 个运算符，以及 4 个可分解 JSON 的表值函数；具体函数清单与 JSON5 行为见 [[160027260de741c1a7101afc370f3478]]（JSON Functions And Operators）。注意 3.44.0 没有 JSONB 与 `json_pretty()`。

## 4. 首批资料范围与统计口径

`quake-events` 首批快照的实际可核对范围（由集合聚合查询得到）：

- 行数：300。
- 时间范围：`2024-09-01T00:49:26.519Z` 至 `2024-09-18T07:52:28.320Z`。
- 震级范围：4.5–6.5，均值约 4.814。
- 来源网分布：us 296、ak 2、ci 1、tx 1。

因此任何统计结论都应写成「本快照范围内」：它只覆盖 2024-09-01 至 2024-09-18 的部分记录，且下限被 `minmagnitude=4.5` 截断，**不能**表述为「2024 年 9 月全部地震」或「该月地震活动水平」。另外来源清单记载 `held_out_rows: 181`，说明该快照还有未纳入的保留行，其用途未在资料中说明。

## 5. 资料解释要点

- USGS CSV 输出字段：time、latitude、longitude、depth、mag、magType、nst、gap、dmin、rms、net、id、updated、place、type、locationSource、magSource、horizontalError、depthError、magError、magNst、status。见 [[5096de356c114f489c3fe1de6a0b8e75]]。
- 本库字段映射：`event_id`←id、`time_utc`←time、`updated_utc`←updated、`network`←net、`magnitude_type`←magType、`review_status`←status；`place` 保留英文地名原文，不作翻译改写。
- `magnitude_type`（如 mb、mww）表示震级标度不同，跨标度直接比较震级大小需谨慎，不应默认同质。
- `review_status` 为 reviewed 表示该事件已被复核；自动解与复核解可能随时间修订，`updated_utc` 是修订时间。
- USGS API 所有时间默认 UTC、ISO8601；`limit` 上限 20000，超过返回 400；`starttime` 默认 NOW-30 天；不指定 `format` 默认返回 quakeml。见 [[81946667edd34bd78e8385c299303d47]]。
