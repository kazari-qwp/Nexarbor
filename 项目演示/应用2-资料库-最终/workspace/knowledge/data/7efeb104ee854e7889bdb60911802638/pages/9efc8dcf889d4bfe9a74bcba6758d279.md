# SQLite 版本边界（项目当前 3.46.0）

需求 v2 把项目可用版本从 3.44.0 升到 **3.46.0（2024-05-23）**。本页按「当前可用 / 仍不可用 / 已失效的历史结论」三部分记录，避免把不同版本的说明混用。历史版本的判断见 [[requirements-v1]]。

## 1. 当前 3.46.0 可用（累计包含 3.44.0 与 3.45.0 的新增）

来自 0009（3.44.0，记录 14445ea2a7b3464fbbf8f42c096638f3，版本 1）：

- 聚合函数可带 `ORDER BY`；新增 `concat()`、`concat_ws()`、`string_agg()`。
- `strftime()` 新增 `%e %F %I %k %l %p %P %R %T %u`。
- 许多 `CREATE TABLE` 错误改为立即报出；`PRAGMA case_sensitive_like` 弃用等。

来自 0010（3.45.0，记录 a4c9e46495ff4c15bb9436d590ae9595，版本 1）：

- JSON 函数改用 **JSONB** 内部解析树；JSON 生成函数输出二进制 JSONB；`json_valid()` 增加第二参数（flags）。
- 新增 `SQLITE_RESULT_SUBTYPE`；FTS5 `tokendata`；`SQLITE_DIRECT_OVERFLOW_READ` 默认开启。

来自 0011（3.46.0，记录 3bdc3627becd44de847740bd6f45186f，版本 1）：

- `strftime()` 新增 `%G`、`%g`、`%U`、`%V`；日期时间新增 `ceiling` / `floor` 修饰符。
- 数值字面量允许下划线 `_`；新增 `json_pretty()`。
- 修复 `->` / `->>`：右侧「看起来像整数的字符串」仍按字符串处理。
- `PRAGMA optimize` 增强；`VALUES` 协程化；解析器栈溢出改为堆分配。

结论：在当前版本上**可以依赖 JSONB**（BLOB 存储、避免重复解析），也可以使用 `json_pretty()`、`strftime()` 的 `%G/%g/%U/%V`。这与 v1 时代「不能依赖 JSONB」的判断相反，旧判断已作废。

## 2. 仍不可用（晚于 3.46.0）

- `jsonb_each()` / `jsonb_tree()`：3.51.0（2025-11-04）起提供（0005 第 4.24 节，记录 3f96bb93535940a698476d077dadd85e，版本 1）。
- `->` / `->>` 右侧使用负整数下标：3.47.0（2024-10-21）起支持（0005 第 4.10 节）。
- 其他 3.47+ / 3.51+ 特性同理，不应写入当前方案。

## 3. 已失效的历史结论

| 旧结论（v1，3.44.0 时代） | 现状（v2，3.46.0） |
| --- | --- |
| 不能依赖 JSONB，`jsonb_*` 不可用 | 已失效：JSONB 与 `jsonb_*` 标量函数可用 |
| `json_pretty()` 不可用 | 已失效：3.46.0 可用 |
| `strftime()` 的 `%G/%g/%U/%V` 不可用 | 已失效：3.46.0 可用 |
| 0009（3.44.0 发行说明）代表当前能力 | 已失效：仅作历史记录，当前能力以 0010、0011 为准 |

`jsonb_each()` / `jsonb_tree()`、`->` 负下标两条旧限制仍然成立（见第 2 节）。

## 4. 资料陷阱

- 0005《JSON Functions And Operators》页面更新于 **2026-07-01**，远晚于 3.46.0：其函数清单同时含有 3.45.0、3.46.0、3.47.0、3.51.0 的特性。引用时必须看该页每条函数下标注的「added with version …」，不能整页照搬。
- 3.45.0 的 JSONB 变更影响「JSON 生成函数返回文本还是二进制」：跨版本迁移旧数据时需评估，尤其是把 JSON 文本存成 BLOB 的历史库（0005 第 3.8 节的 BLOB 输入兼容问题）。
- 升级到 3.46.0 后仍需确认本机构建是否包含 JSON 支持（3.38.0 起默认内置，可用 `-DSQLITE_OMIT_JSON` 关闭，见 0005 第 2 节）。

## 5. 使用建议（基于原文，不是新增验证）

- 需要频繁读取同一 JSON 值时优先存 JSONB；只在 SQL 中临时处理文本 JSON 时继续用 `json_*`。
- 与旧版本或外部工具交换时保留文本 JSON 形式，避免把私有 JSONB 格式当作交换格式（0005 第 3.2.1 节：JSONB 仅限 SQLite 内部使用）。
- 任何「3.47+ 才支持」的写法不要进入当前实现。
