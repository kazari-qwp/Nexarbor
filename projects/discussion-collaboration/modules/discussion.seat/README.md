# 讨论席位（discussion.seat）

把真实 Agent 在讨论组中的角色与显示名称登记为一个轻量模块，供讨论会话沿成员频道发现。组件不运行模型、不保存发言，也不修改 Agent 的人格、上下文或工具。

仅支持 `agent` 节点；普通地点、文本和脉冲节点不能装配。

## 配置

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `role` | 枚举 | `member` | 席位角色：`leader`（主持）、`recorder`（记录）、`member`（普通成员） |
| `name` | 字符串 | 空 | 显示名称，最多 40 个字符；留空或只含空白时使用节点名称 |

配置是装配规则，运行时不写入状态。

## 操作：describe

- 频道：`discussion`（成员发现），也允许 `discussion`
- 参数：无（空对象）
- 返回：

```json
{"id": "节点 ID", "name": "显示名称", "role": "member"}
```

每次成功调用都会先通过 `ctx.publish_metadata({"role": ..., "name": ...})` 在本模块命名空间发布元数据，再返回同一份席位信息。讨论会话因此可以沿成员频道调用 `describe`，也可以读取该命名空间的元数据。

只接受访问调用（`activation.kind == "access"`）；信号激活或未知操作返回中文错误，不发布元数据。

## 装配

1. 在真实 Agent 节点上装配本模块。
2. 按讨论组需要填写 `role` 和 `name`。
3. 给模块授权 `discussion`（需要读取侧时可同时授权 `discussion`）。
4. 让讨论会话的节点沿成员频道可达这些 Agent，调用 `describe` 即可获得席位。

同一网络可装配多个实例，每个 Agent 的角色、名称和发布内容互相独立。角色或名称变化后再次调用 `describe` 即发布会话可读的新值。

## 限制

- 不校验调用者身份，也不代表发言权限；发言与记录由讨论箱等业务组件负责。
- 不维护成员列表；讨论会话通过自己的可达路径和 `discussion` 频道发现席位。
- 元数据只发布 `role` 和 `name`，不包含发言、模型会话或状态。

## 测试

测试位于 `tests/test_discussion_seat.py`，使用真实 `ModuleHarness` 覆盖三种角色、空名称回退、元数据发布、两种频道、默认配置、多实例隔离、非 Agent 装配拒绝及清单声明；并使用真实有向边验证默认配置下跨节点消费、弱边不可达拒绝，以及 `describe` 不改变 Agent 输入与工具。
