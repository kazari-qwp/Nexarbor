# 局部资源转交

让真实 Agent 把自己 `records.store` 中的数字资源转交给另一位当前可达的真实 Agent。组件不写死城镇、货币或物品名称，资源字段、行动点成本和是否要求同地点都由配置与请求参数决定，可用于 NPC 赠物、转账或其他协作资源。

## 装配

本组件挂在 `agent` 节点上，依赖同节点的 `records.store` 与 `place.info`。发起者、收件人以及需要参与记账的节点都应装配 `records.store`；双方都应装配 `place.info`。

模块访问需明确包含：

```json
{
  "strength": 3,
  "channels": ["self", "records", "movement", "social"]
}
```

其中 `self` 用于本 Agent 自己的公开操作入口；`records` 用于内部记账，`movement` 用于读取双方地点，`social` 保留给内部读取和转交路径。这些是可用业务频道的示例，网络也可用双方接受的统一关系频道；小镇使用 location/road，无需把每种业务名都写进边。收件人必须从发起者当前可达。无需为其他 Agent 铺设 `self` 出边：赠送工具只应出现在资源所有者自己的工具列表中。

## 配置

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `cost` | 非负整数 | `1` | 每次成功转交从发起者记录的 `ap` 字段扣除的行动点。 |
| `same_location` | 布尔 | `true` | 为真时双方 `place.info.read` 的 `location` 必须相同且非空；为假时只要求收件人可达。 |

同一份组件可以挂在不同 Agent 上，用不同配置区分交易规则、赠送成本或是否限定同地点，不需要为每个 NPC 复制实现。

## 调用

公开操作 `give` 使用 `self` 频道，参数为：

- `recipient`：另一位真实 Agent 的节点 ID，必须当前可达。
- `resource`：自己记录仓中要转交的数字字段名，例如 `gold`、`wood` 或 `ap`。
- `quantity`：正整数数量。
- `key`：可选非空幂等键。相同键和相同参数重试会返回旧结果并标记 `duplicate: true`；相同键换参数会被拒绝。

Agent 工具“赠送物品或资源”直接调用该操作。工具只能由模块所在 Agent 本人使用；其他 Agent 即使拿到工具入口，转调时也会因请求者不是资源所有者而被拒绝，不能替你赠送。

成功结果为：

```json
{
  "from": "发起者节点",
  "to": "收件人节点",
  "resource": "gold",
  "quantity": 3,
  "ap": 4,
  "duplicate": false
}
```

`ap` 是发起者转交后的剩余行动点。转交 `ap` 本身时，转交数量与行动点成本会合并到同一次增减中，不会互相覆盖。

## 安全与一致性

只有 `requester_id` 等于本节点的真实 Agent 才能送出自己的资源。组件会锁住双方，在锁内重新读取地点、自己的资源数量和 `ap`；余额或行动点不足、地点不符、不可达、记账失败都会整体回滚。幂等回执内部键包含模块实例、节点、请求者和操作步骤命名空间，并由本节点保存最近 200 条，避免同一用户键跨实例复用导致少扣款。
